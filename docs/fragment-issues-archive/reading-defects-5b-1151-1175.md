### Row 5b-1153

*Moved from the register on 2026-11-17.*

**Defect.** **A PROOF'S FINGERPRINT COVERS ONLY THE FRAGMENT'S `impl/` FOLDER, SO A PROVEN CAPABILITY STAYS KEEPABLE AFTER ITS CARD'S CONTRACT CHANGES, ON A REVIT RELEASE IT WAS NEVER PROVED ON, UNDER A CHANGED ADD-IN, AND ON A PATH ITS PROOF NEVER TOOK.** Found 2026-10-18 by the agent-architecture audit - read only, at `4192360`, nothing run in Revit. `Fragment.proof_files` hashes every file under `impl/` and nothing else (`brain/heron_fragment.py:1086-1096`; `fingerprint` at `:1098-1149`), and [D-117](../decisions/D-117.md)'s gate asks only the status and that fingerprint (`unproven_refusal`, `mcp/client/heron_bridge_client.py:1400-1442`, called at `mcp/server/heron_mcp_server.py:1833`). Four things a proof rests on are outside it. (1) **The card's contract:** `fragment.yaml`'s needs, defaults and optional flags are read again on every call (`bridge.fragment_needs`, `heron_mcp_server.py:1851`), so a changed default or a need made optional changes what runs while the proof still reads current. (2) **The Revit release:** `unproven_refusal` never compares the Revit in front with the proof's `model:` line or the card's `revit:` list, and `revit_change` does not ask `_revit_version` at all when a capability is named, so a capability proved only on 2024 is kept on 2020. (3) **The add-in:** `RevitFragment.cs`'s binding, `Describe` and Keep box are not hashed, so a proof taken under one add-in stays current under the next. (4) **The path:** `unload-links` is PROVEN on a run with no transaction open (its proof, 2026-09-14) and Revit refuses it inside one ([row 73](../fragment-issues/section-5-rows-051-075.md), measured both ways); since [row 5b-350](../fragment-issues/section-5b-rows-326-350.md) its only door is `revit_change`, which opens one. **Not checked:** how many PROVEN cards' `fragment.yaml` changed after their proof date, and whether a chat has kept a change on a release no proof names.

**State.** **MOVED TO ISSUE [#914](https://github.com/Ajmalpshaik/Heron-AI/issues/914) 2026-11-16** - still open, tracked there; this row is kept whole. Was: **OPEN - recorded, not repaired; the owner's call, because it decides what a proof means.** What a repair would be: the fingerprint takes in the card's `contract:` block; the gate refuses a release the proof's `model:` line does not name (the line `heron_matrix.proven_releases` already reads); the proof records the add-in version and the path, read or write, it ran on, and the gate compares both.
