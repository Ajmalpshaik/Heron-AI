### Row 5b-1561

*Moved from the register on 2026-11-17.*

**Defect.** **NO REPLY OF HERON'S IS FLAGGED MCP `isError`, AND WHETHER ANY SHOULD BE IS NOT SETTLED.** Decided 2026-11-12 with [row 5b-1159](../fragment-issues/section-5b-rows-1151-1175.md): not set, by any tool, for any ending. **What is known.** The MCP SDK sets the flag itself when a tool raises, and for a crash the model is then given only *"Error executing tool"* and the tool's name - the exception's text stays on the server (SDK 2.3.0, `mcp/server/mcpserver/exceptions.py`). The MCP schema the SDK ships (`mcp_types`, the 2025-11-25 and 2026-07-28 revisions) says of the flag that errors from a tool go in the result *"with `isError` set to true ... Otherwise, the LLM would not be able to see that an error occurred and self-correct"*, and says nothing of what a host must show. A refusal is Heron working correctly, and an outcome nobody knows is the one thing a chat must not be invited to try again. **What is not known:** what Claude Code, or any other host, does with a flagged result - show its text to the model, hide it, or retry. The specification's site could not be reached from the session that built this, and a web search returned reports that hosts differ, which nothing here verified. **One ending still reaches a host flagged, and it is the SDK's:** a door whose own code raises BEFORE its request leaves - nothing was sent, and the model is told only that the tool failed. Once the request has left, the door answers `OUTCOME UNKNOWN` itself and nothing is flagged (`heron_server_core._after_it_left`, since the review of 2026-11-12): a tool that *failed* is what a chat sends again, and by then the change may have been made.

**State.** **MOVED TO ISSUE [#908](https://github.com/Ajmalpshaik/Heron-AI/issues/908) 2026-11-16** - still open, tracked there; this row is kept whole. Was: **OPEN - a question, and it needs a real chat.** On the owner's PC: a tool that answers with text and the flag set - is the text in the model's context, and does the host call again? If the text arrives and nothing is retried, the flag fits two endings and no others: Revit could not be reached at all, and a tool that failed in Heron's own code. Never a refusal, a rollback, a run still going or an unknown outcome. `tests/test_outcome_line.py` section 6 holds today's answer: no outcome is flagged.
