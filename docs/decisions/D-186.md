### Context

On 2026-11-19, on Revit 2020, the Claude app restarted in the middle of a family build. The same modeller
in the same chat window was refused on every call for about three minutes: *"Model ... is in use by
another chat"*. The other chat was the same conversation before the restart. D-141 made a chat's
conversation a random id, once per MCP server process; the restarted app started a new server, so the
same chat came back a stranger to the model it held.

### Decision

1. **The MCP server's conversation is the host's own name for the chat, when the host gives one.** Claude
   Code puts the chat's session id in the server's environment (`CLAUDE_CODE_SESSION_ID`), and a chat it
   resumes keeps that id. The server, when it is run, makes its conversation from it - a hash, so the
   session id itself never leaves the PC and the conversation is still random and meaningless on the
   wire and in the add-in's log. The same chat after a restart is then the same conversation, and the
   add-in's hold lets it straight back in.
2. **Only the server does this.** A command line run from the chat's own shell inherits the same
   variable and keeps a conversation of its own, as D-141 says: it hands back what it held when it ends,
   and that must never free the chat's models. `HERON_CONVERSATION_ID` still wins wherever it is set.
3. **A host that names no chat leaves D-141 as it was** - one random conversation per server process.

### Alternatives considered

- **Free every hold when the server stops.** Not taken: a process killed by an app restart may run no
  clean-up at all, and freeing on exit would hand the model to another chat in the gap the modeller is
  waiting to come back from.
- **Say the holder is the pre-restart copy of this chat and offer to take it.** Not taken: the add-in
  cannot tell the copy from a second chat of the same person without the host's name for the chat - and
  with it, nothing needs to be offered.

### Consequences

- A resumed chat is answered at once; a new chat is still refused while the old one holds the model, as
  D-141 designed.
- A chat forked from another (a new session id) is a new conversation.
- Whether the Claude app on the owner's PC resumes a chat with its session id unchanged is NOT RUN here:
  NEEDS-CHECKING OR1.
