### Context

A QA checklist run ends in the chat and on the Companion's QA Checklist page, which can save it as CSV or
print it. A coordinator sending results to a project team needs a file they can attach: a workbook to
sort and filter, and a page anyone can open.

### Decision

1. **`heron_checklist` `run` takes `report`**, false unless the modeller asks. True writes the finished run
   - or a run that stopped part way, with its NOT RUN rows saying why - to **one Excel workbook and one HTML
   page**, and the reply names both files.
2. **Where:** `<data home>/checklists/reports`, beside the saved checklists. Each file is named for the
   checklist, the model and the minute it was made, in characters Windows allows.
3. **Never written over.** Each file is created new; a name already taken gets " (2)", " (3)" and so on.
   A report can never replace one already sent.
4. **What it holds** - the same as the run: every check's result word (PASS, FAIL, NO DATA, NOT RUN), what
   was read, coverage, change since the last run, severity, clause, why, advice for a FAIL, and the failing
   element ids; the counts, the coverage line and any finding. PASS is said as *meets the value checked*,
   and the page says whether a model complies is the engineer's or the authority's decision.
5. **The modeller's words are data.** The page escapes every value and has no script; it fetches nothing,
   so it opens the same in an email or on a PC with no network. The workbook holds only text and numbers,
   never a formula, so a sentence starting with "=" stays text.
6. **Nothing is read from Revit again**, and nothing in the model is touched. A report that cannot be
   written costs only the report; the run's answer stands.
7. **Standard library only** - no package added to what Heron installs.

### Not in this decision

**BCF issues** and **a picture per failing check**. BCF needs each failing element's position and a
camera, read from Revit during the run; a picture needs [D-123](D-123.md)'s capture, which has not run in
Revit. Both are listed as not built in [docs/50 §7](../50-qa-checklists.md).

### What is not known

Nothing of it has run on a modeller's PC. It is tested without Revit by
[`tests/test_checklist_report.py`](../../tests/test_checklist_report.py), which failed on the code before
it was written. Whether Excel opens the workbook without a repair prompt is the first thing a run on a PC
should look at; the workbook was read back here as a zip of well-formed XML, not opened in Excel.
