### Context

[F42](../proposals/f42.md) item 2: which standards govern a Qatari project - which edition of ASHRAE 62.1,
whether ASHRAE 90.1 applies, CIBSE beside ASHRAE, the QCS edition - could not be established from any
source the HVAC engine was built from, and each one changes what an answer may check. F42 proposed asking
once per project and remembering it, as D-33's *asks once* allows.

### Decision

1. **Four questions, asked together, once per project:** `ventilation_standard` (an ASHRAE 62.1 edition,
   or other), `energy_standard` (an ASHRAE 90.1 edition, other or none), `qcs_edition` (a QCS edition, or
   none) and `cibse_beside_ashrae` (yes or no).
2. **Asked only by the calculations they change** - `ventilation`, `exhaust`, `cooling_load`,
   `monthly_load`, `chw_flow`, `fan_power` and `pipe_size`; `python brain/heron_hvac.py` marks each one
   *asks once per project*. A standard handed to any other calculation is named IGNORED.
3. **Never a blocker.** Until they are known the calculation still runs: the four are put at the top of the
   answer as *ASK ONCE FOR THIS PROJECT*, and each check that needs one says it was not run.
4. **Kept for that project and no other:** one file per project in Heron's knowledge folder,
   `projects/<key>.hvac.json`, named by the Project Information UniqueId the open model reports - the key
   the project's own store is named by. **A chat that has not yet read the model keeps nothing**, and the
   answer says so: Heron does not guess which project this is.
5. **Changed by saying it again.** A value in a request wins over the record and replaces it, and the old
   value stays in the record's history.
6. **What the answers change.** An edition other than the one Heron's tables and clauses are from
   (62.1-2022, 90.1-2022) is named beside each figure and check it touches; a project not governed by 62.1
   is told the Ventilation Rate Procedure is a comparison; 90.1's coil, fan power and pipe-size limits are
   raised only on a 90.1 project; a QCS 2014 project's load answer carries what QCS 2014 is reported to
   set and that it was never read in the text; CIBSE beside ASHRAE says Heron holds no CIBSE data.

### What it accepts

- **`heron_hvac` writes one small file.** In Heron's own knowledge folder - never the model, never a file of
  the modeller's - the same kind of bookkeeping the project label index already does on a read. Its risk
  stays READ, and [`heron_tools.py`](../../mcp/server/heron_tools.py) says why.
- **The file is data, not an index.** It is written whole and moved into place; one that cannot be read is
  set aside under a new name and kept, never overwritten.
- **Until the model is read in a chat, the four are asked every time** there. That is the price of never
  guessing the project.

### Consequences

- **Easy:** the second HVAC answer on a project asks no standards question at all.
- **Owed:** one run with a real model open - read anything from it, ask an HVAC calculation twice, and see
  it ask once. Built and tested here against a stand-in project key; not yet run against Revit's own.
