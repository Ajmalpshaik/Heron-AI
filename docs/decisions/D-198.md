# D-198 — Agents that were built but that nothing in Heron called are retired, and their code and tests removed

### Context

[Docs 28](../28-agent-registry.md) lists 252 agents, and 241 were built: each is a source file whose `Heron-Agent`
header names it. Built is not used. On 2026-11-24 every built agent was sorted by who calls it, by following imports
from each entry point and reading the maintainers' own prompts:

- **105** are reached by the Heron that a modeller uses: the Revit add-in, the MCP server and what it imports, the
  installer.
- **49** are reached by a maintainer's tool: `tools/`, CI, or the helper agents in `.claude/agents` and
  `.codex/agents`.
- **84** were called by nothing but their own tests. Six of them turned out to be used by the maintainers' helper
  agents after all (`heron_generate`, `heron_matcher`, `heron_duplicates`, `heron_merge`, `heron_apply` and what they
  import), so they stay.

That left **78 agents** whose code ran only under its own test. Every suite passed, so the code worked. It was never
called.

**That first count was loose, and too generous.** A file that only named a module in a comment counted as using it.
That could only keep an agent, never remove one, so the 78 stand. A strict count afterwards accepted only a real
import, a load or a command that runs the file. Of the 160 agents left with code, **90** are reached by the
Heron a modeller uses and **35** by a maintainer's tool, and **35 more are called by nothing** - among them the
company-standards agents in `heron_company.py`, `heron_agents.py`, `heron_update.py`, `heron_trust.py` and
`mcp/server/heron_workflow.py`. Five files of agents that are otherwise used are not called either. Those are
the owner's to decide, and this decision does not touch them.

### Decision

1. **The 78 agents are RETIRED.** Their registry rows stay, marked *RETIRED 2026-11-24 by D-198* with what each was
   for, so an id cited anywhere still resolves and nobody builds one again by mistake.
2. **Their code is removed:** 77 `brain/heron_*.py` modules, plus `brain/heron_provider.py` - not an agent, but its
   only job was to call the Model Router, one of the 78. Their own tests and their 77 contracts in `brain/agents/` go
   with them. Git history keeps every line.
3. **`tools/agent-count.py` counts RETIRED as its own state**, beside DEFERRED: built once, removed on purpose, and
   neither built nor left. A retired row needs a decision's name on it, the same rule as a deferral.
4. **An agent comes back only as a real capability a modeller or maintainer can reach**, wired to an entry point,
   with its own decision. Clash / Coordination, Safe Mode and the ISO Standards check are the likeliest.
