### Context

Merging `CHECK_VERTICAL_CLEARANCE` into `CHECK_MINIMUM_CLEARANCE` met one opposite rule: where two boxes overlap,
the minimum card reported a 0 mm gap and the vertical card reported CLASH with the depth of the overlap. One tool
cannot do both by itself, so the owner was asked which.

Separately, `PROPOSE_MEP_OPENINGS` sized a hole as the service plus twice the allowance, with no insulation term,
while `CHECK_SLEEVE_SIZE` required twice the insulation as well - so a hole proposed for a lagged pipe read
UNDERSIZED when the sleeve check ran with the same gap.

### Decision

1. **How an overlap reads is the modeller's choice, given in the request, and both answers are kept.** A clearance
   check that measures pairs which can overlap takes an option for it: **CLASH with the depth** of the overlap -
   boxes and jackets together - or **0 mm**. Left out, it is **CLASH with the depth**: a 0 mm gap reads as two things
   just touching and hides how far one has to move, and a CLASH is reported whatever clearance was asked, so an
   overlap can never pass. Either way the overlapping pairs are counted, and a gap column never holds a negative
   number. On `CHECK_MINIMUM_CLEARANCE` the option is `overlapAs` - `clash` (the default) or `zero`; any other word
   measures nothing and says so.
2. **A hole or sleeve is sized round a service's insulation when the model says the service carries some, and only
   then.** Whether a pipe or a duct carries insulation is read from the model first - the wraps Revit lists on it -
   and, when it does, twice the thickest wrap is added to the size; when it does not, nothing is added, and the
   answer says which. Never an assumed thickness, and lining - inside a duct - is not insulation. `PROPOSE_MEP_OPENINGS`
   and `CHECK_SLEEVE_SIZE` read it the same way.

### Consequences

- `CHECK_MINIMUM_CLEARANCE` version 5 answers an overlap as CLASH with its depth unless asked for `zero`, which
  gives version 4's answer exactly; `PROPOSE_MEP_OPENINGS` version 3 adds insulation where it is modelled. Both
  are DRAFT until Group QY is run on a real model.
- A clearance check written later that can meet an overlap offers the same two answers and the same default.
- An assumed thickness is still the caller's to give where a card takes one (`assumeThicknessMm`), said on every
  row it touches - this decision is about what is read from the model, not about what may be assumed on request.
