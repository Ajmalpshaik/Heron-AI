### Context

[F45](../proposals/f45.md) confirmed, by reading the code on 2026-11-16, that Changes, Admin and Publish are
each one line in `%APPDATA%\Heron\config\heron.config`: writable by every program running as the
modeller, read fresh on every request, with a line added at the end winning. Heron's own refusal told the
chat to *"set write.enabled = true in"* that file, and heron-guard allowed every file outside the
repository. So an AI host with file access could turn writing on, and Heron's own words told it how.
**Seen in code, not tested.**

### Decision

F45's design, in its three layers and in this order:

1. **Layer 1 - heron-guard refuses it as it is proposed.** A second rule refuses a write to a file named
   `heron.config`, anywhere on disk, that would turn on `write.enabled`, `admin.enabled` or
   `publish.enabled`, and any text naming layer 3's registry key. The hook's matcher widens to Bash,
   PowerShell and the MCP tools that write files. Reading the file stays allowed. Deny-tier, every refusal
   a diary line, `HERON_GUARD=off` the hatch. Kept after layer 2 as a tripwire.
2. **Layer 2 - the three switches are held in Revit's memory.** Pressing ON in Heron's Settings window,
   with D-106 item 5's question on the way on, is the only way to set one. The three keys leave
   `HeronConfig`'s defaults and `heron_config.DEFAULTS`, so a line in the file is ignored like any key
   Heron does not declare. **All three are OFF every time Revit starts** - the owner's choice - and each
   Revit holds its own. No refusal or message names the file; each names Settings. No operation on the
   pipe sets a switch, as none does today.
3. **Layer 3 - an administrator's ceiling.** The add-in reads `HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Heron`:
   `AllowChanges`, `AllowAdmin` and `AllowPublish` at 0 mean that switch cannot be turned on on this PC;
   missing or 1 means the modeller may, as in layer 2. No key, no ceiling.

### What does NOT change

- **Ask to Keep and the Companion** stay in `heron.config`, as D-126, D-138 and D-150 have them.
- **[Article 7](../../HERON_CONSTITUTION.md)**: no switch is the yes it asks for before a delete, a purge, a
  workset change or anything touching a link.
- **What each switch lets through** is D-106's, unchanged: Admin and Publish each still need Changes.

### What it accepts

- **One click after each Revit start**, instead of once - the owner's choice, told so before choosing.
- **What none of the layers stops**, from F45: a program that drives Revit's screen as the modeller
  presses the button as a person would; a program that writes into Revit's memory on purpose; an AI
  running as administrator can write layer 3's key; layer 1 sees only the hosts that load this
  repository's settings, and not a script that writes the file another way. An older Heron still
  installed for another Revit year reads the file until it is updated, so every year's add-in is
  updated together.

### Layer 2 built, 2026-11-16

The same word, *"yes, build it, start with the hook"* - layer 2 next, as item 2 above says:

- **`HeronPermissions` holds Changes, Admin and Publish** as three fields under one lock, set only by
  `SetWriteEnabled`, `SetAdminEnabled` and `SetPublishEnabled`, which only the Settings window's
  commands call. A static field starts false, so all three are **off whenever Revit starts**. Decisions
  are made from one `HeronSwitches` snapshot - the gate in `RevitOperations`, the run guard's second look
  in `HeronRunPolicy.Withdrawn`, and `Explain`.
- **`HeronConfig` and `heron_config.DEFAULTS` no longer declare the three keys**, so a line naming one is
  ignored like any unknown key, and the next `Save` drops it. A restored backup cannot turn one on.
- **No refusal or message names the file.** Each says the modeller turns the switch on in Heron's Settings
  in Revit, and that only the modeller can - *"no file, setting or request turns it on"*.
- **Each Revit's `info` reply carries `changes`, `admin` and `publish`**, and `revit_health` prints a line
  for each Revit from them (`heron_bridge_client.switches_state`, `heron_health.switches_line`). The
  health rollup no longer reads writing from this side's file.
- **The questions and the Settings window say it**: *"This stays on until you turn it off or close Revit -
  it is off again every time Revit starts"*, and under the switches, *"All three are off whenever Revit
  starts."*

**Evidence.** `tools/check-compile.py`: all 27 projects compile on Revit 2020 to 2027 (a Linux container).
`tests/Heron.Kernel.TestHost` section 8: every combination of the three switches at every level, the three
keys refused by `HeronConfig.Set`, a fresh process holding all three off, and refusals naming Settings and

### Layer 3 built, 2026-11-16

The same word, item 3 above. **The ceiling lives in the add-in, behind a hook in the kernel:**

- `HeronPermissions.Policy` is asked on every decision, the shape of `HeronAudit.ReportLoss`, so the kernel
  still depends on nothing. Unset, there is no ceiling; a reader that throws or answers nothing holds all
  three off - **it fails closed**.
- The add-in sets it at start-up to `HeronMachinePolicy.Read` (in `HeronApplication.cs`), which opens
  `HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Heron`. `AllowChanges`, `AllowAdmin` and `AllowPublish` are
  DWORDs: **0** holds that switch off, **1 or missing** lets the modeller turn it on, any other kind of
  value is read as 0. No key is no ceiling. A registry fault reads as unreadable - all three off.
- **A ceiling that comes down turns the switch off for good**: the held value is cleared, so lifting the
  ceiling again turns nothing on - only a press in Settings does.
- Held off, a switch's Settings row says *"Held off on this PC by its administrator."*, pressing it asks no
  question and says who can help, and the refusal says *"held off on this PC by a Windows policy ... only
  the PC's administrator can lift it"*. The `info` reply carries `changesLocked`, `adminLocked` and
  `publishLocked`, and `revit_health`'s line names them.

**Evidence.** `tools/check-compile.py`: every project compiles on Revit 2020 to 2027.
`tests/Heron.Kernel.TestHost` section 8: a ceiling holding Changes off refuses ON and Modify and keeps
reads, its refusal names the administrator and no file, a ceiling that came down and went up again leaves
the switch off, Admin held off alone leaves Changes working, and a policy that throws or answers nothing
holds all three off. `tests/test_config_and_health.py` reads the locked fields and the health line.
**Nothing of it has read a real registry**: [Group OB](../needs-checking/group-ob.md) OB6 and OB7.

**Seen while building it:** layer 1 refused this session's own shell command that carried a
`reg add ... Policies\Heron` line meant for Group OB's text (Group OA until main took those letters) - the tripwire working, on a false positive.
Text like that is written with the editor, not a shell heredoc; the heron-guard skill says so.
