### Context

Article 17 of the [Constitution](../../HERON_CONSTITUTION.md) says a credential never goes into a source file
or a commit, and this repository is public (D-07), so one that reaches `main` is published to every clone
at once and cannot be called back. [12 §5a](../12-security-and-permissions.md) asked for two layers: a
redactor on the way out, which `brain/heron_secrets.py` is, and a scan before anything is published. On
2026-10-18 both 12 and [17](../17-open-source-and-distribution.md) recorded the scan as **not built**.
[CONTRIBUTING.md](../../CONTRIBUTING.md) closes a change that carries a credential without review, which is
a reviewer's check - and a reviewer reads the diff, not the tree.

The gap was found again on 2026-10-18 by a second reading of an external project's secret scanner
([33 §5.1](../33-external-repository-research.md#51-affaan-mecc)). Three things were already true in Heron
and decided the shape: `heron_secrets.PATTERNS` already held the credential shapes; `.gitignore` already
held a **Secrets** block of file names; and `heron_commit.stage()` reads a commit **message** for a
credential but never the files being committed.

### Decision

1. **`tools/check-secrets.py` is a gate in the job named "The gates that must pass".** A finding fails
   the pull request and blocks a release - the owner's word, *"Block it"*. A report would be read after
   the merge, and a credential cannot be un-merged.
2. **It reads the contents of every tracked file against `heron_secrets.PATTERNS`**, the redactor's own
   list, and holds no list of its own. A shape added there is caught here with no edit.
3. **It reads the name of every tracked file against the Secrets block of `.gitignore`**, matched by git
   (`git ls-files --cached --ignored`), so a `!` line there means what git says it means. `.gitignore`
   stops a new file; a file added with `git add -f`, or tracked before its line was written, is exactly
   what it misses. Case is ignored on every system, because git's own rule follows `core.ignorecase` -
   true on a Windows checkout, unset on the Linux runner - and a gate that passed `.ENV` in CI while it
   failed on the owner's laptop would decide nothing. With no entries in the Secrets block, or a tracked
   file it cannot open, the run exits **2** - it does not pass on a typed guess or on a file nobody read.
4. **It never prints a value** - a finding is a file, line, column and shape, and a file name goes
   through the redactor before it is printed, because a name can be a token too.
5. **There is no allow-list.** A test that needs a token-shaped fake builds it from pieces, as
   `heron_secrets.FAKE_FORGE_TOKEN` already did. The two literal fakes the tree held, both in
   `tests/test_configuration.py`, were rewritten that way, with what that test checks unchanged.
6. **`PATTERNS` gains a private key.** Neither the scan nor the redactor recognised one, while
   `heron_configuration.SECRET_SHAPED` did. PEM's and PGP's both. In a log the whole block is redacted
   when its END line follows within 16 KB, and the BEGIN line alone when it does not - bounded, because an
   unbounded search from every BEGIN to the end of the text made a long log cost its BEGIN lines times
   its length, and let an unrelated END swallow everything between.

### What this does NOT change

- **History is not read.** A key committed and later deleted is still in every clone. A key that was ever
  pushed is public: rotate it, whatever the gate says today.
- **It is not a pre-commit hook.** It stops a merge, not a local commit - the same place every other gate
  stands.
- **No PII scan** - the other half of 17's item 3 - is built.
- **`heron_configuration.SECRET_SHAPED` is still a second list of shapes**, and `heron_commit.stage()`
  still does not read the files it stages. Both are recorded, not fixed here
  ([row 5b-1138](../FRAGMENT-ISSUES.md)).

### Consequences

The job runs twelve gates, not eleven, and every place that lists the current gates says so. A file that is not
text is counted and not read, and the count is printed, so a clean run never claims more than it read.
Measured 2026-10-18 on this checkout: every tracked file read in under three seconds, no finding.
