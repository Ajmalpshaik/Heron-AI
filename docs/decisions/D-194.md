### Context

D-23 chose SQLite with its extensions for the three stages of finding a fragment, and named sqlite-vec for the
meaning stage. sqlite-vec was never wired: `_try_vec_extension` has had no caller since it was written
(`75d06767`, 2026-08-28), so on every machine every stored vector has been compared in Python, whether
sqlite-vec was installed or not. Since 2026-11-15 `heron_embed.comparison()`, printed by `tools/heron-ready.py`,
says so (PROPOSALS F7). What was left was a decision that said one thing while the code did another
(row 5b-1171): a caller for sqlite-vec, or a decision bringing D-23's words to what runs.

Comparing in Python gives the same answers - one dot product per stored vector - and asks nothing of the
machine. Loading an extension is refused on some Python builds, the locked-down machines D-01 is written for.
D-23's own revisit rule asks for a measured slow query before anything more is built; none has been recorded.

### Decision

1. **Every stored vector is compared in plain Python**, over the bytes kept in the scope's own SQLite file. That
   is the meaning stage on every machine.
2. **sqlite-vec is not used.** Nothing in Heron loads it, and installing it changes nothing.
3. **Revisit only on measurement**, as D-23 says: a measured query time against a real scope that is too slow.
   A change to the comparison then needs a new decision.

### Alternatives considered

A caller for sqlite-vec, used where it loads: two paths for one comparison, the faster one absent exactly where
extension loading is refused, and nothing measured to say Heron needs it.

### Consequences

- D-23 stands for SQLite, one file per scope, FTS5 and the exact match; its sqlite-vec words are history.
- `comparison()` names this decision, and still says whether sqlite-vec happens to be installed - installed or not,
  it changes nothing.
- sqlite-vec leaves Heron's install lists - `requirements-optional.txt`, `brain/heron_dependencies.py`,
  `tools/cloud-setup.sh` and `tools/heron-ready.py`'s snapshot list - and `_try_vec_extension`, which never had a
  caller, leaves the code; done in the same change, on the owner's word *"do #1194 too, in this PR"*
  ([row 5b-1955](../fragment-issues/row-5b-1955.md)). A cloud environment whose setup script is an older copy of
  `tools/cloud-setup.sh` still installs it until the script is pasted again.
