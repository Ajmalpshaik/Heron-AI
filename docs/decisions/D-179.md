### Context

An office has one QA standard and many projects. Each project needs the same checks with small changes:
a lower severity, a looser limit, a check that does not apply. Today each project copies the office list,
and the copies drift apart without anyone seeing it.

### Decision

1. **A project list `extends` one office list, by name, and may add checks of its own.** Its
   **`overrides`** each name an office check by its exact words and change **only** its severity, its
   rule's target, or whether it runs at all (`enabled`). Anything else is refused when saved.
2. **One level only.** An office list extends nothing, so two lists can never extend each other, and a
   list cannot extend itself.
3. **What a project list runs is saved whole beside its overrides**, so the list, the Companion's page and
   every other reader work on it as on any list.
4. **At each run the office list is read again**, so a change to it reaches every project. The run says
   so when the office list changed since the project list was saved. If the office list is deleted, now
   extends another list, or changed so that an override no longer matches, the run uses the copy saved
   with the project and says why. It never fails silently, and never runs half of each.
5. **Every run names the checks it used** by a fingerprint of twelve hex characters: the same checks give
   the same fingerprint, and any change gives another. It is on the run's answer and in the report,
   beside the office list's name.
6. **Team folders are not in this decision.** An office list is saved like any other list, on one PC.
   Sharing it across a team is [docs/50 §7](../50-qa-checklists.md) item 3, still the owner's to decide.

### What is not known

Nothing of it has run on a modeller's PC. [`tests/test_checklist_extends.py`](../../tests/test_checklist_extends.py)
holds it without Revit, and failed on the code before it was written.
