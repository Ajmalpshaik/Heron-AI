# D-109 — A Companion button in Revit opens the page, and a Companion switch turns it off without touching Heron

> One record of [the decision log](../DECISIONS.md). It was given its own file on 2026-09-29 so that it
> can be read alone. Decisions are append-only: to change one, write a new decision that supersedes it.

**Status:** Accepted · **Date:** 2026-09-29 · **Source:** Ajmal PS, 2026-09-29, in conversation, after the first Companion run in Revit 2024: *"we need one more button that if I press the button in Revit it will open this companion app ... one more settings that I can turn off this connection for companion app directly ... if I turn off the companion app I can still use the Heron AI"*
**Amends:** [D-108](../DECISIONS.md#d-108--the-modeller-can-see-and-edit-herons-work-in-a-local-companion-page-and-the-chat-stays-the-only-place-to-talk-to-heron) point 1 - the page is served while the Companion switch is on, not only once a chat asks for it · **Keeps:** D-108 otherwise, [D-02](../DECISIONS.md#d-02--mcp--add-in-transport-named-pipes), [D-92](../DECISIONS.md#d-92--a-ribbon-button-is-a-front-door-onto-a-proven-fragment-not-new-logic)
**Affects:** [`HeronCompanionCommands.cs`](../../revit/Heron.Revit.Addin/HeronCompanionCommands.cs), [`HeronApplication.cs`](../../revit/Heron.Revit.Addin/HeronApplication.cs), [`HeronLiveState.cs`](../../revit/Heron.Revit.Addin/HeronLiveState.cs), [`HeronConfig.cs`](../../platform/Heron.Core/HeronConfig.cs), [`HeronPaths.cs`](../../platform/Heron.Core/HeronPaths.cs), [`heron_config.py`](../../mcp/client/heron_config.py), [`heron_companion.py`](../../mcp/companion/heron_companion.py), [`heron_mcp_server.py`](../../mcp/server/heron_mcp_server.py)

### Context

The Companion's first run on the owner's PC (NEEDS-CHECKING [group BK](../needs-checking/group-bk.md),
Revit 2024) showed **Connected** and **3 ducts**. Revit felt slow, and the owner checked it himself:
**just as slow with the Heron button disconnected**, when the Companion does no work at all - so the
Companion was not the cause. He then asked for a way to open the page from Revit, and for a switch that
turns the Companion off on its own, leaving Heron working.

### Decision

1. **A Companion button on the Heron tab**, beside Changes, Admin and Publish. Pressing it opens the
   chat's Companion page in the default browser. Its arrow holds **Turn Companion off / on**. The picture
   is the switch's state: blue while on, grey while off.
2. **The switch is `companion.enabled`** in `heron.config`, declared in both halves of the settings,
   **on by default** - the page only shows, so it defaults on for the activity banner's reason
   ([D-50](../DECISIONS.md#d-50--revit-says-out-loud-what-heron-is-doing-to-it-and-whether-it-is-reading-or-changing)).
   No confirmation either way.
3. **Off means off, and Heron is untouched.** The add-in deletes its live file and writes no more; within
   two seconds every chat's page stops and its note is removed. The Heron button, the chat, the pipe and
   the Changes, Admin and Publish switches are exactly as they were.
4. **While the switch is on, each chat keeps its page ready** (this amends D-108 point 1, *"on
   request"*): a keeper thread in the chat's MCP process reads the switch every two seconds, starts or
   stops the page, and keeps a note in `%LOCALAPPDATA%\Heron\companion\chat-<pid>.json` naming the port
   and a **single-use** code. The keeper touches no pipe - the step where Talk's listener stalled
   ([D-105](../DECISIONS.md#d-105--talk-is-removed-and-the-modeller-works-with-heron-in-the-chat-only)) is
   not in it - and a fault in it never reaches the chat.
5. **The Revit button reads that note and hands the address to Windows.** Revit opens no socket
   ([D-02](../DECISIONS.md#d-02--mcp--add-in-transport-named-pipes) and [revit/README](../../revit/README.md)
   rule 3 stand): it is the same act as a hyperlink. It picks the chat bound to this Revit, else the newest
   still running; a note left by a chat that crashed is ignored. With no chat running it says so and does
   nothing.

### Why D-92 does not apply

[D-92](../DECISIONS.md#d-92--a-ribbon-button-is-a-front-door-onto-a-proven-fragment-not-new-logic) makes
every ribbon button that does BIM work a front door onto a proven fragment. These two do no BIM work and
touch no model: like the Heron button and the three padlocks, they are controls for Heron itself.

### What it accepts

- **A chat now runs a small local web server whenever the switch is on**, whether or not the page is
  open - on `127.0.0.1`, protected as [40 §11](../40-heron-companion.md) says. The switch is how to stop it.
- **The note holds a code a program running as the same Windows user could read and use once.** The same
  trust the bridge's discovery file already rests on.
- **The chat's own `heron_companion` refuses while the switch is off**, and says where to turn it on.

### Consequences

- **Easy:** the page from Revit in one click; a clean off with Heron unaffected.
- **Hard:** a restart of Revit for the new button, and of the Claude app for the keeper.
- **Owed:** rows added to NEEDS-CHECKING [group BK](../needs-checking/group-bk.md).
