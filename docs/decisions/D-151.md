### Context

A modeller repeats the same job - the same capability with one or two values changed - many times a
week, and today types it into a chat each time. The owner asked for a way to save a job once and run it
again with a click, from a panel docked in Revit like Dynamo Player.

### Decision

1. **The chat saves a command** with `heron_commands`, only when the modeller asks: a name, the ONE
   capability that ran, its values, and the values to ask each time written as `{input}` with a label and
   a default. It is checked against the fragment's own contract when it is saved, and refused whole if a
   value or input does not fit.
2. **The Heron panel lists and runs them** - a dockable pane opened from **Commands** in the Heron
   button's menu (the ribbon keeps its three things, D-150). A new command appears in it without
   restarting Revit.
3. **A run goes through the chat's own door.** The panel touches no Revit API; it starts
   `heron_command_run.py`, which calls `revit_change`'s or `revit_read`'s own body. So the PROVEN rule,
   the switches, the model pin, the one-conversation hold and Keep or Discard all apply as they do to a
   chat, and nothing about them is copied into C#.
4. **One saved command is one capability** - Article 8's one click, one undo. **PUBLISH and ADMIN jobs
   are never saved** as a button: a sync, export or new workset is asked for in a chat each time.
5. **Personal first.** Commands live in `%USERPROFILE%\.heron\commands\personal`. Sharing with the team is
   not built.

### Consequences

- **Easy:** a repeated job is one click and its inputs; the run needs no AI, so it costs nothing and does
  the same thing every time.
- **Hard:** the panel needs Python and the Heron folder, which it learns from the note a chat leaves when
  it starts - **a PC where no chat has ever started cannot run a command** (it cannot have saved one
  either). A command cannot chain two capabilities until a decision allows several steps under one undo.
- **Not proven:** compiled for Revit 2020 to 2027 and tested without Revit; never run in a real Revit.
