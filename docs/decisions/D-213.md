### Context

D-189 made updating the main Heron folder - the one a modeller's chat opens from - the owner's own step, because on
2026-11-19 a session's pull there stopped a modeller's job half-way. Sessions since then handed the owner a
`git pull --ff-only` line to run. On 2026-11-28 he asked them to stop handing it to him and do it themselves.

D-189 had considered *"pull only after checking that no Heron server runs from that folder"* and not taken it,
because a check can miss a chat about to start. The owner now takes that risk, with the checks below in front of it,
and the cost of a miss stays bounded: Group EU's guard stops the open chat's next change and asks for it to be
reopened, so a model is never changed by code it did not start with.

### Decision

1. **A session brings the main Heron folder up to date itself, with `git pull --ff-only origin main` and nothing
   else, and does not hand the owner the command** - when every one of these holds, checked just before:
   - no Revit job is running: `revit_health` shows no Revit connected, or none in the middle of a job;
   - the folder is on `main`, and `git status --porcelain` is empty;
   - there is no `.git/index.lock` - no other git command is running there;
   - no other session is busy on a Revit job from that folder.
2. **A check that fails is said, by name, and the session waits.** It never works round one, never forces, resets,
   stashes or deletes anything there, and a pull that will not fast-forward is reported, not resolved.
3. **After a pull it says that new chats get the new code**, and that a chat already open keeps the code it started
   with until it is reopened.
4. **Everything else in D-189's item 1 stands:** no checkout, merge, rebase or rebuild in the main folder.

### Consequences

- AGENTS.md says it under "How to work".
- A chat already open from the folder can meet Group EU's refusal after a pull - asked to reopen, never a changed
  model. That is the guard doing its job, as on 2026-11-19, and the checks make it rarer.
- **Not checked:** no session has yet pulled under these rules with a modeller chat open from the folder.
