### Context

A coordinator runs the same checks every week, and the first question after a run is *"what got fixed
since last time, and what is new?"* A checklist run said PASS, FAIL or NOT RUN and nothing about the run
before it; a check carried no severity and no reference to the BEP clause it enforces. The comparison D-155
came from scored this 8 to Heron's 5.

### Decision

1. **A check may carry three labels, each optional and the modeller's own words:** `severity` (high,
   medium or low), `clause` (the BEP or standard it comes from, one line, up to 200 characters) and
   `advice` (how to fix a failure, one line, up to 300). Checked when saved; Heron never sets a severity
   and never checks a clause - it quotes it. A checklist saved before these fields reads as before.
2. **A finished run is kept** in `<data home>/checklists/runs/<checklist>/`, beside the saved checklists,
   never inside them: each row's state, value and ids, and which model it read. The newest 20 a checklist
   are kept. A run that stopped part way is neither compared nor kept.
3. **Each run is compared with the newest kept run of the same checklist on the same model** - the pin's
   identity, else the title. A run on another model is never compared. Each check is:
   - **NEW** - failing now, met the value last time;
   - **STILL OPEN** - failing both times, with how many elements came and went when every id arrived;
   - **FIXED** - failed last time, meets the value now;
   - **NOT COMPARED** - not run now or last time, or a check not in the last run. Not run is never a change.
   A check is matched by its sentence, capability and rule, so a reworded check is a new one - never a
   false FIXED.
4. **Said everywhere a run is shown:** one sentence in the chat and on the page (*"Since the last run on
   Tower at 2026-11-12 10:00: 1 new, 1 fixed, 1 still open"*), a **Since last run** column and badge on the
   Companion page, and the labels and the change in the CSV.
5. **Never raises.** A history that cannot be read costs the comparison; one that cannot be written is a
   finding on the run. The run's own result stands either way.

### What is not known

Nothing of it has run in Revit. The comparison runs without Revit in `tests/test_checklists.py` and
through the MCP tool in `tests/test_checklist_tool.py`, whose new checks fail on the code before the
change. [NEEDS-CHECKING Group NV](../needs-checking/group-nv.md) holds the runs.

### Alternatives considered

- **Compare with the previous run on any model.** Two models' differences are not what changed in one.
- **Keep every run.** A folder that only grows; twenty weekly runs is five months of history.
- **Severity set by Heron from the capability.** A severity is the project's decision, written in its BEP,
  not Heron's.
