### Context

Revit gives every element two built-in parameters named "Category" - `ELEM_CATEGORY_PARAM` and
`ELEM_CATEGORY_PARAM_MT` - and a material carries both as well. `COMPARE_ELEMENTS` version 2, holding to
D-54 item 3 through the guard of row 5b-203, therefore said *"'Category' - NOT READ"*, and *"'Category
[type]'"* beside it, for every element in every model (Revit 2024, NEEDS-CHECKING Group NK row NK8,
2026-11-13), and never compared Category at all. Row 5b-1631 recorded it.

D-54 item 3's reason is that *"taking the first match is a wrong answer that looks exactly like a right
one"*. Where every parameter carrying the name is Revit's own and all of them read the same, no match is
chosen: whichever Revit meets first gives the same answer. The first repair read such a name as one value
inside the refusal; `tests/test_same_name_guard.py` failed it in CI, rightly, because the rule as written
refuses every name matched twice, and it was withdrawn until the owner decided.

### Decision

1. **A parameter name carried by two or more parameters on one element, or on its type, is ONE reading
   when every one of them is a built-in** (its `InternalDefinition.BuiltInParameter` is not `INVALID`)
   **and every one reads the same text as Revit displays it.** That value is used as the name's value.
2. **Everything else stays refused, as D-54 item 3 says**: a shared or project parameter among them, two
   built-ins that read differently, or a name Revit will not count.
3. **The reading is a step of its own**, asked only of a name counted twice and before the refusal, which
   is unchanged - it says NOT READ and fills in no value (`test_same_name_guard.py` check 5). Check 7 holds
   the step: built-in on every carrier, one distinct reading, asked only of a doubled name.
4. **`COMPARE_ELEMENTS` takes it first** (version 3, row 5b-1631). Every other reader of row 5b-203 takes
   it only through a change of its own, proved, which adds it to check 7's list.

### What is not known

Nothing of it has run in Revit: it compiles for 2020 to 2027, and [NEEDS-CHECKING Group NX](../needs-checking/group-nx.md)
row NX9 runs NK8's five walls and two room tags again. Whether `ELEM_CATEGORY_PARAM` and
`ELEM_CATEGORY_PARAM_MT` read the same on every element and every release is that row's question; where they
do not, the name stays refused - the rule fails closed. Which other names Revit doubles on an element has
not been looked for.

### Alternatives considered

- **Refuse every doubled name, as D-54 item 3 is written.** Category is then never compared, and every
  comparison carries a NOT READ line that is no doubt about anything - noise that teaches a modeller to
  skip the lines that matter, among them the real doubled shared parameter the rule exists for.
- **A list of known built-in twins to skip by name.** A list of special cases goes stale with the next
  release, and says nothing when two built-ins do read differently.
- **Compare by built-in parameter rather than by name.** `COMPARE_ELEMENTS` gathers what a modeller sees in
  Properties, which is names; and two different built-ins can mean the same thing to the modeller.

### Consequences

A built-in name Revit doubles is compared like any other, and the refusal is kept for the cases D-54 was
written for - a shared or project parameter bound beside a built-in one, or two parameters that disagree.
The exception is narrow and checked, so it cannot spread to a reader by accident.
