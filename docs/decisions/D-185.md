# D-185 — Reload Latest and Sync with Central stay the modeller's own clicks, and Heron builds no route for either

### Context

Revit refuses `Document.ReloadLatest` and `Document.SynchronizeWithCentral` while any transaction group is open, and
every Heron door that may change a model runs inside one (row 5b-1423). Two routes were offered: an add-in route that
runs one fragment with no group open, or a posted Revit command whose result a separate read checks afterwards.

### Decision

1. **Reload Latest and Sync with Central are the modeller's own clicks**, on Revit's Collaborate tab.
2. **No reload card is built**, no route runs a fragment with no transaction group open for them, and no posted Revit
   command is used for either.
3. **`SYNC_WITH_CENTRAL` stays as found** - DRAFT, never run in Revit, and unable to sync inside Heron's group.

### Alternatives considered

- **A route with no group open.** Not taken: a change outside the group is outside the one-undo rule (Article 8).
- **A posted command read back afterwards.** Not taken: it runs after Heron has answered, so Heron could report
  neither Revit's result nor the model after it.

### Consequences

- Nothing in code changed.
