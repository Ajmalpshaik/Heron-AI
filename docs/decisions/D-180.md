### Context

Heron's reply is the conversation, so it reaches the AI provider. A model's full path can say more than
the model does: `C:\Projects\Acme Hospital Phase 2\...` names the client and the job. On 2026-08-28 the
owner answered Q-40: no redaction, because work answers may travel and only the model may not, and the
document's name stays in every answer (Golden Rule 20). On 2026-11-17 he agreed to a build order whose
third item hides folder paths, as a setting. Those two are not the same thing, but they meet.

### What is proposed

1. **A setting, `privacy.hidePaths`, off by default** and declared on both sides like every other setting.
   Off, nothing changes: Q-40's answer stands exactly as it was.
2. **On, every Windows path in a reply to the chat keeps only its last part** - the file or folder name -
   and loses every folder above it: `C:\Projects\Client X\Tower MEP.rvt` becomes `…\Tower MEP.rvt`. A
   drive letter, a network share, either slash and a path written into JSON are all covered.
3. **The document's name is kept.** Golden Rule 20 is unchanged: every answer still names its model. Only
   the folders above the name are hidden.
4. **Applied once,** where every tool's answer leaves for the chat (`_recorded`), and read fresh on each
   answer. The model, the files, the Companion's activity list on this PC and the logs keep full paths.
5. **Not anonymisation.** A file name, a parameter value or a view name can still say what a folder would
   have, and the setting says so.

### Why it is not Accepted

Q-40's answer was *no redaction*. This hides folders only, is off unless turned on, and keeps every
document's name, so it may sit alongside that answer. Whether it does is the owner's decision, not the
build's. **The owner decides:** accept it as written, or drop it and leave Q-40 standing alone. Until
then it is built, tested, and off.

### What is not known

Nothing of it has run on a modeller's PC. [`tests/test_hide_paths.py`](../../tests/test_hide_paths.py)
holds the rule, the setting on both sides and the one place it is applied, and failed on the code before
it was written.
