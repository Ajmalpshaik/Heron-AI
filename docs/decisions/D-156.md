### Context

Since row 5b-407 a write's reply says **which** elements Revit counted as added, modified and deleted,
by category. It says nothing about **how**. *"12 Ducts modified"* reads the same for a 300 mm move and for
ducts Revit only regenerated because a joined wall moved, and the modeller has to look in Revit to tell
which.

### Decision

1. **A write's reply carries `readBack`**: for each element Revit counted as **modified**, every value
   that differs, old and new - its name, its type's name, where it sits (a point and its turn, or a line's
   two ends, in mm) and every parameter, each as the text Revit shows (`AsValueString`, the project's own
   units) or, where Revit gives none, the stored value.
2. **Where the "before" comes from is said in the field (`mode`), because it differs:**
   - **`dryRun`** - a run nobody was asked about and that rolled back (D-155's dry run, a proof's trial).
     Every changed element is read after the run, inside the group, and read again once the rollback
     **held**. Complete up to 50 elements, and exact: nothing is predicted.
   - **`selection`** - a run that keeps. Its old values are gone once it runs, and running it twice to
     read them is what D-126 refused. So **the modeller's selection is read before the run starts**, and
     only those elements are compared. Every other changed element is counted as **not read**, and the
     chat is told a dry run would show them all.
3. **Not read is never "unchanged".** An element missing from either side is counted apart. An element
   read on both sides with no value that differs is counted too - *"regenerated, or hosted or joined to
   what moved"* - which is a real answer and not the same as not read.
4. **Never on a Discard**: what it would have changed is not what the modeller is looking at.
5. **Limits, each counted when reached:** 50 elements read per side, 20 with a difference on the reply
   with 12 values each, a value cut at 120 characters; the chat shows 10 elements of 4 values. What is
   left out is counted on the line, never dropped silently.
6. **It changes nothing and can break nothing.** The reader opens no transaction and sets nothing, and
   every read is caught on its own: one value that throws costs that value, never the change.

### What is not known

- **Nothing of it has run in Revit.** It compiles for 2020 to 2027 and every Revit member it calls exists
  in every release (`tools/check-api-surface.py`); the comparing is run without Revit by
  `tests/Heron.ReadBack.TestHost`. [NEEDS-CHECKING Group NS](../needs-checking/group-ns.md) holds the runs.
- **Whether `AsValueString` reads the same text before and after for a value that did not change.** If a
  parameter's text moved with nothing changing - a timestamp, a computed area - every element would show
  a difference. NS3 is the run that finds out.
- **How long reading every parameter of 50 elements twice takes on a large model.** NS5 measures it.

### Alternatives considered

- **Run the change twice to read a "before" for a kept run.** Exact for every element, and D-126's own
  reason against it: the model can move between the runs, and it doubles every kept change's time.
- **Snapshot every element of the categories the fragment might touch.** No card says which categories a
  fragment touches before it runs, and reading a whole category of a large model on every change is the
  cost this was built to avoid.
- **Read only the values the fragment's card says it sets.** No card declares that, and the elements that
  matter most are the ones that moved without the card meaning them to.
