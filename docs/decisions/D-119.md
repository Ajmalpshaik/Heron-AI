### Context

[Article 11](../../HERON_CONSTITUTION.md) reads: *"Untested code never touches a live model. Generated or
newly imported code runs in a sandbox or against a detached copy first."* It comes from
[Golden Rule 18](../14-golden-rules.md), and [D-04](../DECISIONS.md#d-04--generated-code-execution-hybrid) said that rule
*"is enforced by the sandbox"*. **No sandbox for a fragment was ever built.**
[D-28](../DECISIONS.md#d-28--generated-code-is-c-compiled-at-run-time-in-process) put generated C# inside Revit's own
process, and [D-84](../DECISIONS.md#d-84--the-sandbox-is-renamed-not-rebuilt) took the word *sandbox* off the one module
that had it, because it watched and did not contain.

So today a fragment the author agent writes in a minute waits for a proving session on a test copy,
and the modeller who asked for it waits with it. The author agent keeps Article 11 by its tool list and
the sentence *"You never run it"*. And the rule is not kept anywhere else: `revit_change` already runs a
DRAFT fragment for real, kept at once, with a warning line and no prompt ([D-99](../DECISIONS.md#d-99--a-change-asked-for-in-a-chat-is-kept-at-once-with-no-preview-and-article-9-says-so)).

### The question, as it will be put

> *"When Heron writes a new tool for you, it is DRAFT - never tried. Today it never runs on your model
> until somebody proves it on a test copy. Proposal: let it run ONCE on your model, but only like this -
> the model must be saved, the tool runs as one undo step, Revit shows you the result, and a box asks
> Keep or Discard. Discard, closing the box or pressing Escape puts the model back exactly as it was.
> Nothing stays unless you press Keep. Do you want this (A - I recommend it), or keep the old rule: never
> on a live model, test copy only (B)?"*

### Decision

1. **The sandbox Article 11 asks for is, for a fragment, the run itself inside one `TransactionGroup`,
   held open behind a prompt in Revit.** The fragment runs for real, Revit redraws the view in front, and
   a modal box asks the modeller to keep it or discard it. Keep assimilates the group into one named undo
   entry; anything else rolls the whole group back.
2. **It is a mode of the existing write path, `"apply": "ask"`**, beside `"true"` (keep) and absent
   (roll back, the [D-55](../DECISIONS.md#d-55--a-fragments-preview-is-the-run-itself-rolled-back) preview). Only on
   `run_fragment_write`: the add-in refuses it on `run_fragment_publish`, because a rollback does not
   unwrite a file, and on `run_fragment_admin`, which keeps its own switch and Article 7's confirmation.
3. **Discard is the default.** The default button, Escape and the window's close button all discard.
4. **The model must be the one in front**, because the modeller has to see it, **and saved with nothing
   unsaved** - [D-121](../DECISIONS.md#d-121--d-84s-cost-is-read-again-a-never-proved-fragment-runs-only-on-a-saved-model-with-nothing-unsaved).
   Both are refused before the group opens, so a refusal changes nothing.
5. **Nothing widens.** The run goes through `run_fragment_write`, declared Modify in the operation
   registry, so Changes must be on ([D-19](../DECISIONS.md#d-19--writing-is-off-by-default-until-the-write-path-has-met-a-real-revit)).
6. **The command line reaches it in one place**: `heron_bridge_client.py try-once <fragment>`, which
   refuses anything but a DRAFT at risk MODIFY, and refuses a second run of a version that was already
   kept. Who may start it, and when, is [D-122](../DECISIONS.md#d-122--under-article-19-the-modeller-judges-a-drafts-one-run-and-the-agent-that-wrote-it-only-starts-it).

**Article 11, as it will read once this is accepted** (the Constitution is not edited before then):

> **11. Untested code never touches a live model.**
> Generated or newly imported code runs in a sandbox or against a detached copy first.
> **One recorded exception, D-119:** a DRAFT fragment may run once on the saved model in front, as one
> named undo step behind Heron's Keep or Discard prompt in Revit - that prompt and that one group are its
> sandbox. Nothing it did stays unless the modeller, having seen the result, presses Keep.

Golden Rule 18 gains a *"Broken once, on the record"* paragraph naming this decision, the way Golden
Rule 17 names D-99.

### What stands in for the sandbox

| | Where |
|---|---|
| **One group, rolled back unless kept.** Every write the fragment makes is inside it | `RevitFragment.Run` - the `TransactionGroup`, then `AskTheModeller` before `Assimilate` |
| **Revit's failures answered by Heron, never resolved by Revit** - an error rolls the whole run back | `Discipline`, on every transaction the write path opens |
| **The rollback is reported as Revit reported it**, never as asked for | `SafeRollBack` returns Revit's status; the reply's `rolledBack` |
| **A person decides, in Revit.** Nothing on the wire answers the box | the modal `TaskDialog` in `AskTheModeller` |
| **The model in front, saved, nothing unsaved** - checked before anything runs | `RevitFragment.Run`, above the group |
| **Changes on**, read inside the add-in | `HeronPermissions`, `run_fragment_write` at Modify |
| **Runaway recursion is a finding, not a dead Revit** | `HeronStackGuard` |
| **The wait for the modeller is not a timeout.** The dispatcher waits `revit.askTimeoutSeconds` more for a job that has put the box up | `RevitDispatcher.Dispatch` |

### What this does NOT change

- **`revit_change` is untouched.** It still keeps a DRAFT's change at once ([D-99](../DECISIONS.md#d-99--a-change-asked-for-in-a-chat-is-kept-at-once-with-no-preview-and-article-9-says-so)).
  This decision adds a safer door; it does not close the older one.
- **A kept run is not a proof.** What it may count as is [D-120](../DECISIONS.md#d-120--a-run-the-modeller-kept-after-checking-it-is-the-positive-case-of-a-proof-and-the-negative-case-is-still-its-own-rolled-back-run).
- **`write.enabled` stays off by default.**

### Known limits, said before anybody meets them

- **The box is modal, so the modeller sees the view that was in front and cannot pan, zoom or select
  while it is open.** A change that cannot be judged from that view is discarded, a view that shows it is
  opened, and the run is asked for again.
- **A rollback undoes what the fragment did to the model, never what it did outside it** - a file
  written, a setting saved. A MODIFY fragment doing that is mis-declared; the author's checks are what
  keep it from being written, and this path cannot catch it.
- **A loop that never ends freezes Revit** until Revit is ended - the reason for item 4's *saved*.

### Alternatives considered

- **B - keep Article 11 as written.** Safe, and the modeller waits for a proving session for every tool
  written on the spot.
- **Run it on a detached copy automatically.** Heron never opens a project - *"opening a project is a
  decision with a lock and a load time behind it"* (`RevitFragment.Run`) - and a copy of a workshared
  central carries its own hazards.
- **Roll back, show the counts in the chat, then run again with `apply`.** The code runs twice, the
  second time unseen, and the modeller judges a count instead of the model.

### Consequences

- The Constitution's Enforcement table names this path beside Article 11 once accepted.
- The author agent's *"You never run it"* becomes *"you run it once, this way, when asked"*.
- **NEEDS REAL REVIT** until a run has been kept, a run has been discarded with the undo list unchanged,
  and a kept run has become an accepted proof - [NEEDS-CHECKING](../NEEDS-CHECKING.md) Group EM.

### Merged beside D-117 - 2026-10-17

**Two sentences above describe `main` before [D-117](../DECISIONS.md#d-117--a-change-is-kept-only-from-a-fragment-whose-proof-still-stands)
reached it, and are left as they were written.** *"`revit_change` already runs a DRAFT fragment for real,
kept at once"* and *"It still keeps a DRAFT's change at once"* were true when this decision was written and
accepted. D-117, accepted the same day and merged first, made `revit_change` and `fragment --write --apply`
refuse a kept change from any fragment whose proof does not stand. So this decision's path is now the
**only** way a DRAFT's change is kept, and the two decisions agree: D-117 closes the door that had no
prompt, and this one is the door with one.

**One question D-117 left open touches this path, and it stays the owner's.** D-117 asks whether
[D-35](../DECISIONS.md#d-35--a-shared-fragment-may-carry-code-and-an-unapproved-one-is-refused-not-warned-about)'s
*"no warning dialog, ever"* rules out a Keep or Discard route for the owner's own DRAFTs. This decision is
that route and the owner accepted it; whether that acceptance also settles D-35's reach is recorded here as
asked, not answered. D-117's own `unproven` field for `revit_change` is not built by this decision -
`try-once` sends `"apply": "ask"`, which an older add-in reads as a rollback, never as a keep.
