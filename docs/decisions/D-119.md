### Context

D-30 promotes a fragment on one recorded proof against a real model: a positive case, a negative case
that comes back empty, and a second route where one exists. Today the positive case is a run rolled back
on a test copy, judged by a person reading the counts it returned.

A run kept through D-118's prompt is the same run with one thing added: **the modeller looked at the
model in Revit and pressed Keep.** It also has one thing missing - nobody arranged a case where the answer
had to be empty, so it says nothing about *succeeded and did nothing*, which is what D-30's negative case
exists to catch.

### The question, as it will be put

> *"When you press Keep after checking a new tool's result in Revit, may that run count as the 'it
> worked' half of its proof? The 'it does nothing when it should do nothing' half would still be its own
> run, rolled back, and you would still sign the proof with your name. (A) yes - I recommend it; (B) no,
> every proof is run fresh on a test copy."*

### Decision

1. **A run kept through the prompt is D-30's positive case.** Its record says it was kept by the
   modeller after seeing it in Revit, with the date, the model and what the fragment returned.
2. **For the exact code that ran, and no other.** The record carries a hash of the source that was sent.
   `validate --kept` refuses to use it once the fragment's code has moved, and so do `draft` and `accept`.
3. **The negative case is never taken from a kept run, and never kept.** It is its own run, rolled back -
   `validate --write --kept` runs only the negative leg and the second route, and puts the kept run in the
   positive's place. D-53's tracking cannot stand in here: its first input IS a positive run.
4. **A discarded run is no evidence for the positive.** It is recorded as discarded, and `validate --kept`
   refuses it.
5. **Signing is unchanged.** `accept --by` takes a person's name, writes the proof block, and never the
   status. Promoting is the owner's separate act.

### Alternatives considered

- **Count the kept run as the whole proof.** It has no negative case, and D-30 says a proof without one
  is not a proof.
- **Re-run the positive on a test copy.** Twice the work, and the kept run already showed it on a real
  building.

### Consequences

- The kept run is recorded at `brain/proof-drafts/runs/<fragment>.once.json`; `validate --kept` writes the
  ordinary `runs/<fragment>.json` with that run as its positive phase, so `accept` re-reads one record as
  it always has.
- A proof's positive case may now name the modeller's own model. D-26 is unaffected - the record stays on
  the machine, and `runs/` is gitignored.
