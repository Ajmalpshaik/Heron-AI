### Context

Row 5b-472's duplicate check found cards that do one thing by two rules (row 5b-1879). Three were the owner's
to choose, because each pair held the opposite rule: a name pattern `CHECK_FAMILY_STANDARDS` read as *contains*
and `CHECK_MODEL_STANDARDS` read as a `*` wildcard on the whole name, so `TRG` passed any name holding TRG in one
and only a name exactly TRG in the other; a name already taken, which `CREATE_PROJECT_REFERENCE_PLANES` skipped
while `CREATE_GRIDS` and `CREATE_LEVELS` refused the whole call; and a link placed more than once, which
`REPORT_LEVEL_ELEVATIONS` measured through its first placement while `CHECK_DATUMS_AGAINST_LINK` refused until
one placement was named.

### Decision

1. **A name pattern is a `*` wildcard on the whole name, case-insensitive**, in every tool that takes one.
   `TRG*` starts with TRG, `*MEP*` holds MEP anywhere, and a pattern with no `*` is the whole name.
   `CHECK_FAMILY_STANDARDS`' `namePattern` changes to it; an old value written for *contains* - `MEP` - now
   matches only a name that is exactly MEP, and is written `*MEP*` to do what it did. Its card says so at the
   input.
2. **A datum maker skips a name already taken, makes the rest, and the answer lists each skipped name with the
   reason** - one rule for reference planes, grids and levels. A name another element of that kind already has
   in the project, or an earlier one in the same call, ignoring capitals, is not made; `skipped` holds one line
   for it - the name and what holds it - and everything else asked for is made. Only a call whose every item is
   skipped makes nothing, and its `refused` says so, so the answer never reads as a change.
3. **A link placed more than once is never measured through one of its placements until the modeller names
   which.** The answer names every placement and asks; it never takes the first. A placement a copy-monitored
   datum monitors is named by that monitoring - Revit records which copy - and is measured for those datums.

### Alternatives considered

- *Contains* for both pattern tools: loses the whole-name rule that `CHECK_MODEL_STANDARDS` adopted after its
  bare pattern quietly passed `Supply Diffuser OLD` for `Supply Diffuser`.
- Refusing the whole call on a taken name, as grids and levels did: safe, but one clash in a long setting-out
  stops the whole job, and the owner chose the skip.
- Measuring through the first placement and saying so: a plausible number from a copy nobody chose.

### Consequences

- `CHECK_FAMILY_STANDARDS`, `CREATE_GRIDS` and `CREATE_LEVELS` were PROVEN; their C# changed, so each is DRAFT
  with its version raised until [NEEDS-CHECKING Group QZ](../needs-checking/group-qz.md) is run on a scratch model
  and signed by the owner. `CHECK_MODEL_STANDARDS` and `CREATE_PROJECT_REFERENCE_PLANES` did not change and stay
  PROVEN.
- A family standard written as `namePattern: MEP` fails every family not named exactly MEP until it is
  rewritten `*MEP*`. That is the narrower reading, and the card says it at the input.
- Rule 3 is carried out in the datum tool merged from `REPORT_LEVEL_ELEVATIONS` and `CHECK_DATUMS_AGAINST_LINK`
  (row 5b-1878 (C)), in its own pull request; `CHECK_DATUMS_AGAINST_LINK` already refused.
