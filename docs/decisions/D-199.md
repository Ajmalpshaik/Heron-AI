### Context

D-198's strict count, which accepts only a real import, load or run, found 35 agents that nothing in Heron calls.
The owner was shown them and chose for each group.

### Decision

1. **Kept, and still idle:** the company-standards agents (`heron_company.py`, `heron_convention.py`,
   `heron_corroborate.py`, `heron_exemplar.py`, `heron_modelqa.py`). They are to be wired in later.
2. **Kept, and now named:** the agent registry, `brain/heron_agents.py`. It is a maintainer's command that prints
   one agent's whole record, and [AGENTS.md](../../AGENTS.md) now points at it.
3. **Retired, and their code removed**, each because something that already works does the job, or a decision
   rules the job out:

| Module | Agent | Why it is not needed |
|---|---|---|
| `heron_update.py` | `HERON-OPS-UPD-010` | The installer's own update check, in `platform/Heron.Installer`, is what runs |
| `heron_trust.py` | `HERON-KRN-TRU-019` | The MCP server applies Golden Rule 19 in its own code |
| `heron_release.py` | `HERON-RPT-RED-003` | No report export called it |
| `heron_tag.py`, `heron_versioning.py` | `HERON-GIT-REL-007`, `HERON-GIT-VER-008` | Releases are built by `.github/workflows/release.yml` and `tools/build-release-assets.py` |
| `heron_import.py`, `heron_classify.py`, `heron_walk.py`, `heron_placement.py`, `heron_index.py`, `heron_belongs.py` | `HERON-IMP-APR-014`, `-CLS-003`, `-FIL-002`, `HERON-WSP-PLC-005`, `HERON-IMP-IDX-013`, `-ARC-011` | An import pipeline; [D-25](D-25.md) says other libraries are studied and re-authored, never imported |
| `heron_commit.py` | `HERON-GIT-CMT-004` | The host writes commits; it only fed the retired release agent |
| `mcp/server/heron_workflow.py` | `HERON-KRN-WFL-007`, `HERON-KRN-STA-005` | The host runs the steps ([D-01](D-01.md)) and Heron makes one change per call; nothing imported it |

4. **The rows stay in docs/28**, marked RETIRED by D-199, as D-198's do.
5. **`heron_exemplar.py`** read one value, the rung an imported pattern enters at, off `heron_import.py`. It now
   reads the same value, `heron_fragment.STATUSES[0]`, directly, so the standards chain keeps working.
