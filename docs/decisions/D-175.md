### Context

`revit_undo_last` ([D-157](../decisions/D-157.md)) sends Revit's own Undo for Heron's last kept change in a model.
The add-in kept one entry per model and nothing about which chat kept it, so a chat could undo a change another
chat made ([Q-88](../open-questions/tier-2.md)). On 2026-11-15 Claude decided it on the owner's delegation -
*only the chat that made a change may undo it* - and it was built and compiled on 2026-11-16, not run in Revit.
The Activity pane's Undo button ([D-163](../decisions/D-163.md)) did not work at all
([row 5b-1741](../fragment-issues/row-5b-1741.md)), and whether the pane may undo any chat's change was asked apart.

### Decision

1. **A chat undoes only its own change.** `revit_undo_last` is refused, with nothing sent to Revit, when Heron's
   last kept change in that model was kept by another chat. The refusal says so and that Ctrl+Z in Revit still
   undoes it.
2. **The Activity pane's Undo is the modeller's own click in Revit, like Ctrl+Z**, so it undoes Heron's last kept
   change in the model on screen whichever chat made it - still only under D-157's rule, and never reachable by a
   chat as a way round point 1.
3. **Ctrl+Z in Revit is never limited by Heron.**

### Alternatives considered

- **Any chat may undo any chat's change.** Asked in those words and declined: *"own only"*. "Undo that" typed in
  the wrong window would take back another chat's work.
- **Remove the pane's button.** Declined: the owner wants it to work.

### Consequences

- Q-88's refusal stands as built; its two-chat run is owed ([Group NU](../needs-checking/group-nu.md), NU34 to NU40).
- The pane's Undo is built to point 2 ([row 5b-1741](../fragment-issues/row-5b-1741.md)); its run is owed (Group NW).
