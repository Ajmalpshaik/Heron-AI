### Context

A QA check that failed offers **Select in Revit** for the elements that failed. A failing list of ids
arrived as its count and first three (`RevitFragment.Describe`), so a check that found 40 unplaced rooms
said *"Heron received 3 of the 40"* and offered no Select at all - rather than select part of what failed.
docs/50 §7 named this as the first thing not built.

### Decision

1. **A request may name lists in `sendIds`.** The add-in sends **every id** of each list named - a list of
   `ElementId`, or of elements by their `Id` - in `providesIds`, as `{"name": {"total": N, "ids": [...]}}`.
   Anything else named is left out, never guessed at.
2. **Only when named.** No other reply changes: `Describe`'s count-and-first-three stays byte for byte, so
   every proof record and `heron_validate` read the same.
3. **Up to 5,000 ids a list** (`IdsSentPerList`), the total always beside them. A list longer than that is
   known to be incomplete, and Select is not offered for it.
4. **A QA check names its own ids output on its one read**, through the server's side channel set around
   that read and cleared after it - never `revit_read`'s schema, which every chat pays for.
5. **Select in Revit is offered when every id arrived.** The Model Dashboard's route still selects at most
   its own limit and says *"the first N of M"*.

An add-in from before this ignores `sendIds`; the run then says the add-in sent the first three, and that
an updated one sends them all.

### What is not known

Nothing of it has run in Revit. It compiles for 2020 to 2027; the Revit-free halves are
`tests/test_checklists.py` and `tests/test_checklist_tool.py`, whose new checks fail on the code before
the change. [NEEDS-CHECKING Group NV](../needs-checking/group-nv.md) holds the runs.

### Alternatives considered

- **Send every list of ids whole, always.** Every reply grows with the model, and every proof record's
  shape would change.
- **Raise `Describe`'s three to a larger number.** The same, smaller - and still not "all".
