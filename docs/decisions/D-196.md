### Context

D-156 put each changed element's old and new values on a write's reply - for every element **Revit counted as
modified**. An element the job was given and Revit did not count was not mentioned at all: neither *not read*
nor *no difference*. A pinned, hosted or constrained duct a move left where it was simply vanished from the
answer, and the chat could read "3 ducts moved" for a job handed four.

The move path already compares every element's position before and after and reports `blocked`
(`RevitWrite.Verify`), and some cards say it themselves: `MOVE_ELEMENTS` counts `blocked`, and
`MOVE_VIEW_CUT_PLANE` reads its cut plane back. Others do not: `MOVE_ANNOTATION`'s point mode and
`MOVE_TO_RAY_HIT` count an element moved once Revit's call returns, and read no position back (read
2026-11-21, not run). Research note 51 named the lesson; row 5b-1903 recorded the gap; the owner said yes.

### Decision

1. **Handed means bound to the card's needs**: every Element and ElementId among them, alone or in a list, in
   the order they were bound - the same reading as the rollback check's (`RevitReadBack.HandedTo`). **Never the
   modeller's selection on its own**: a selection the card was not given is not what it was asked to change.
2. **At the moment the "after" is read** - inside the group, after Revit's change report is sealed and before
   the Keep box, Assimilate or the rollback - every handed element **still in the model** that Revit did **not**
   count as modified is named: **asked, did not change**, by id and category. One Revit has deleted, or that
   cannot be read, is not named: it is not "did not change".
3. **It is said as Revit's count, never as a cause and never as a failure.** A card that only reads some of
   what it is handed - the hosts it tags, the level it places on - lists those too. Whether the card was meant
   to change an element is the card's to say, not this list's, and the chat's line says so.
4. **On the same replies as D-156's read-back**: a kept change and a dry run, never a Discard (item 4). A keep
   Revit counted nothing in is rolled back by D-160 and carries no read-back; its verdict already says nothing
   was changed. A dry run that changed nothing still names what it was handed.
5. **Limits, each said when reached:** the first 50 handed are checked (`MostRead`), and the reply says when the
   job was handed more; the reply names 20, the chat 10, and counts the rest.
6. **It changes nothing and can break nothing**, as D-156 item 6: one getter per element, each caught on its
   own; the chat checks the field whole and prints one line saying it could not be read rather than lose the
   reply.

### Alternatives considered

- **Compare only a card's own result list** (`moved`, say) with Revit's count. Every card would need a result
  list in one shape, and they do not have one - `MOVE_TO_RAY_HIT` counts, and many writes have none.
- **A role on each need** - "changes this" or "only reads this" - so only what a card means to change is
  checked. Truer, but a contract change to every write card, which nobody asked for; the wording in item 3
  carries the difference until then.

### Consequences

- The reply's `readBack` gains `handed`, `handedAll`, `askedNotChanged`, `askedNotChangedElements` and
  `askedNotChangedMore` - only when the check was made, so an add-in from before it never reads as one that
  looked and found nothing. The chat prints one line, *"asked, did not change: N of the M element(s) this job
  was handed - Revit counted no change to them: ..."*.
- A tag or place card's reply now lists its hosts as asked, did not change. That is true and expected; the
  line's own words say a job that only reads some of what it is handed lists those too.

### What is not known

- **Nothing of it has run in Revit.** It compiles for 2020 to 2027, every Revit member it calls exists in every
  release (`tools/check-api-surface.py`), and the rule and the chat line are run without Revit by
  `tests/test_read_back.py`. [NEEDS-CHECKING Group NS](../needs-checking/group-ns.md) NS13 holds the run.
- Whether a pinned element makes Revit's move throw or stay put in silence. The check reads Revit's count
  either way, and NS13 writes down which.
