### Context

`CREATE_SHEETS_FROM_TABLE` makes sheets from a spreadsheet's sheet register in one call and fills their parameters,
from the table [`heron_sheet_list.py`](../../brain/heron_sheet_list.py) reads out of an `.xlsx` or `.csv`. It was built
on 2026-11-09 for [docs/48](../48-studying-bimlogiq.md) item 7 and signed PROVEN on 2026-11-13. Row 5b-1486 left four
choices to the owner.

### Decision

1. **A blank cell writes nothing.** It never clears a value the sheet holds.
2. **A date from Excel goes into a text parameter as an ISO date** - `2026-11-09` - not in a project's own format.
3. **A value Revit refuses is listed, and its sheet is kept** - the row is not taken back whole.
4. **1,000 rows is the most one call makes.**
5. **The four hold for whatever card carries this job later**, the planned merge into `CREATE_SHEETS` included.

### Alternatives considered

An empty cell that clears; a project date format; a row taken back whole when one of its values is refused; another
limit. None was taken: the owner kept all four as built.

### Consequences

- Nothing in code changed. The re-ranked routing run on the owner's PC is still owed ([Group MY](../needs-checking/group-my.md), MY11).
