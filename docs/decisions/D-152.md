### Context

A modeller checks the same things before every issue, and Heron already has a PROVEN read for many of
them. What was missing is the saved list and the one press that runs it - BIMLOGIQ's checklists, studied
in docs/48 and re-authored here, nothing taken.

### Decision

1. **A checklist is a named list of checks**, saved by the chat only when the modeller asks, in
   `%USERPROFILE%\.heron\checklists\personal`. A check is the modeller's sentence, ONE capability, its
   values, and a pass rule on ONE output the fragment declares - `output op number` - with, optionally,
   the output that holds the failing element ids.
2. **A check only reads.** A capability declared above ANALYZE is refused when saved, and the read door
   refuses it again on every run. Each check is checked against its fragment's card when saved: its values
   (the saved command's own check, called), the values it cannot run without, and that the rule's output
   is declared and holds a number.
3. **A run is one read per check, through `revit_read`'s own body**, on the one model the chat is bound to.
   A capability that is not PROVEN, or whose proof is stale, is **NOT RUN** and nothing is sent. From the
   Companion, the lock every tool call holds is taken for each check's read only.
4. **The words are fixed.** PASS means *meets the value checked*; FAIL does not; NOT RUN says why and is
   **never counted as a pass**. Heron never calls a model compliant.
5. **The Companion gets a QA Checklist workspace**: the saved checklists, Run, the results with PASS, FAIL
   and NOT RUN in the brand's Success, Error and Warning, CSV and Print. **Select in Revit is the Model
   Dashboard's own route** (docs/40 §21.11, the owner's *"yes allow select button"*), with the ids the run
   found, only when every one of them arrived.
6. **`heron_checklist` is declared ANALYZE through `run_fragment_read`** - `revit_read`'s level and
   operation - because its run reaches the model through that door.
7. **A starter checklist lives in the code**, every check a PROVEN read that collects its own elements. It
   is never saved by itself; the chat saves a copy under the modeller's name when asked.

### Consequences

- **Easy:** a week's checks are one press; a run needs no AI once saved, costs nothing and changes nothing
  in the model, so there is no undo and no Keep or Discard.
- **Hard:** **a list of more than three failing ids arrives as its count and first three** (D-26), so
  Select in Revit is offered only for a check whose ids all arrived. Selecting all of them needs the
  add-in to send them - a C# change, not made. A check that reads the selection answers about whatever is
  selected when it runs.
- **Not proven:** tested without Revit; never run in a real Revit - [group MV](../needs-checking/group-mv.md).
