### Context

D-104 was accepted on the morning of 2026-09-27 and built as #338: a **Talk** button in Revit that saved
the modeller's words and selection into Heron's derived `talk` folder, and a Claude Code chat, started
by `mcp\heron-talk.cmd`, that took them into the conversation through Claude Code's channels. It had
never met Revit.

The same evening it was run on the owner's PC - Revit 2024, a test copy, NEEDS-CHECKING
[group AS](../needs-checking/group-as.md), where the verdict is recorded row by row:

- **AS1, AS2 and AS3 passed.** The button is on the ribbon and opens its box. Claude Code registered
  Heron's channel - `/status` said *Channels: Listening for messages from server:heron*, and its own
  log for the server said *Channel notifications registered*. With no chat listening, the box refused,
  kept the words and wrote nothing.
- **AS4 failed, in the one way D-104 said Talk never would.** The message was saved at 19:20:10 -
  `message-1.json` and `selection-1.json`, *"3 selected in heron ai bulding"* - and the chat never
  showed it. The chat's listener stopped refreshing at 19:20:07 and did not claim the message. When the
  chat was closed at 19:26:14 the message was claimed in its last moment, renamed `.taken`, shown to
  nobody, and deleted with Revit's folder three seconds later. **The modeller's words were taken and
  lost.** The listener stopped after it found the message and before it claimed it - the step between
  asks the bridge which Revits are live - and went on only when the chat was closed. No stack was
  taken, so the call it waited in is not proven.
- **Found on the way.** The owner's PC had Claude Code only inside the desktop app, so the launcher
  could not start until the terminal one was installed, and a fresh install starts signed out. Its first
  question about Heron's server defaults to *Continue without using this MCP server*. The channel notice
  D-104 promised was folded under *2 more notices hidden*.

The owner, on seeing AS4: *"this is not good, remove this talking thing completely"*, and then *"from
Revit, GitHub codes completely you can remove this related to this feature, I don't want this, do the
housekeeping also."*

### Decision

1. **Talk is removed, all of it.** The Revit button, its window and its mailbox; the `talk` folder's
   path; the listener, the channel and `heron_selection` in Heron's server; the `HERON_TALK` switch and
   the launcher; its tests and its test host. The code is as it was before #338.
2. **The modeller works with Heron in the Claude chat, as [D-01](../DECISIONS.md#d-01--execution-host-claude-code-plugin) chose.** D-01's sentence
   *"nothing is being built for it"* stands again.
3. **The record stays.** D-104 is marked superseded and keeps its words; group AS keeps its checks,
   with what ran and what each showed; the handover keeps its note. A link to a removed file points at
   commit `5b18541a`, the last that had it.
4. **A second attempt starts with a new decision that answers AS4 first**: why the listener stopped
   when a message was waiting, and a proof that a message is either shown in the chat or left where it
   was - never claimed and dropped.

### What it accepts

- **Nothing is kept switched off for later.** Talk was already off unless its launcher was used; code
  that no chat runs is code nothing proves, and the owner asked for it gone.
- **A modeller cannot speak to Heron from inside Revit.** That is the owner's choice, made on the
  evidence of the first run.

### Alternatives considered

- **Find why the listener stopped, fix it, and carry on to AS5-AS10.** Not the owner's choice.
- **Keep the code, switched off.** Rejected by the owner: gone from Revit and from the code.
- **Delete D-104 and group AS as well.** Not done: the decision log and the register are append-only,
  and without them nothing would say why Talk is gone, or stop it being built again the same way.

### Consequences

- **Easy:** one way in again, the chat. Nothing in Revit writes a message file and nothing in Heron's
  server listens for one.
- **Hard:** nothing new to maintain.
- **Locks in:** nothing. What D-104 locked in - the `talk` folder and its file format, the
  `claude/channel` capability, `heron_selection` - is gone.
