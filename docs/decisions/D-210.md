### Context

On 2026-11-27 a session wrote the design for Heron's chat side - the MCP server, the brain, its skills - as a
versioned Claude Code plugin ([the design](../work-notes/plans/claude-code-plugin-2026-11-27.md)), and left three
questions for the owner in its section 9. On 2026-11-28 his local session put to him four items, numbered 2 to 5
there, and asked whether to start building them in small pull requests:

| Item | What it is |
|---|---|
| 2 | Build the plugin |
| 3 | MCP prompts served as slash commands for common jobs |
| 4 | The jobs `heron_method` holds, also served as skills |
| 5 | Allow rules, so a tool that only reads is not asked each time; a change is still asked |

He answered *"Yes, start it"*. The session that started this one also relays that he approved releasing the plugin
from Heron's own GitHub marketplace rather than Anthropic's directory, which does not fit a product that needs a
Windows installer and a Revit add-in; no words of his are quoted for that, so it is recorded here as a relay only.

### Decision

1. **Heron's chat side is built as a Claude Code plugin**, as section 3 to section 7 of the design describe it. The
   Revit add-in still comes from Setup.
2. **In small pull requests, each with one part.** Part 1 is the build script and the folder it makes -
   `tools/build-plugin.py` and `dist/heron-plugin/` - and **publishes nothing**: no marketplace file, no release
   workflow, no Setup change. Those, the slash commands (item 3), the skills (item 4) and the allow rules (item 5)
   are later parts.
3. **The plugin's version is `heron-products.json`'s `manifestVersion`, written by the build**, and
   `check-products.py` fails a built folder that says another number. One number, typed in one place.
4. **Allow rules cover tools that only read.** A tool that changes the model is still asked, in the chat and by
   Revit's Keep or Discard, exactly as today. Whether a plugin can ship allow rules at all is **not confirmed** by the
   documentation read on 2026-11-28; the part that builds item 5 checks it first.

### Alternatives considered

- **Not now** - offered in the question, and not chosen.
- **One large pull request for all four items** - not offered; small pull requests were the question's own words,
  and the owner merges each one himself.

### Consequences

- What a modeller installs does not change until a later part publishes something; Setup still writes the user-scope
  `heron` entry it writes today.
- The plugin keeps the client id the repository's `.mcp.json` carries today, until
  [Q-100](../open-questions/tier-3.md) ([#1488](https://github.com/Ajmalpshaik/Heron-AI/issues/1488)) is answered.
- A plugin version installs into a folder of its own. What in Heron is keyed on its own folder, and which of those a
  new folder per version breaks, is listed in the design's section of 2026-11-28; each break is a register row and an
  issue of its own, not fixed by this decision.
- Nothing here is proven: a built folder is not an install. Section 8 of the design lists the checks owed on a real
  Windows PC.
