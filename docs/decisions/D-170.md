### Context

[D-84](../decisions/D-84.md), accepted 2026-09-20, chose to keep what exists, build no subprocess, and take the
word *sandbox* out, because a new agent's first run is ordinary Python in the supervising process: *"An agent
that cooperates is held. One that does not can call `open()`, import the bridge, reach into globals or delete
files, and nothing is in its way. That is most of the value and none of the guarantee, and the word sandbox
implies otherwise."* Row 5b-52 took the word out of the module, its register row, `DISCLAIMER.md` and
`SECURITY.md`. It stayed in the two places that bind ([F23](../proposals/part-f.md)): Article 11, *"Generated or
newly imported code runs in a sandbox or against a detached copy first"*, and Golden Rule 18, *"New code runs
in a sandbox or against a detached copy."* On 2026-10-17 [D-119](../decisions/D-119.md)'s exception used the word
again: *"that prompt and that one group are its sandbox"*.

The Constitution's Enforcement section says its Articles are assembled into an agent's instructions from the
file, so Article 11 is text an agent may be given - telling it a containment exists that D-84 recorded as not
built. An agent may not weaken an Article, so F23 waited for the owner.

### Decision

1. **Article 11 reads** - F23's draft, and D-119's exception with its one word changed:

   > **11. Untested code never touches a live model.**
   > Generated or newly imported code runs watched — every door shut and every attempt recorded — or against
   > a detached copy first. Watched is not contained (D-84).
   > **One recorded exception, D-119:** a DRAFT fragment may run once on the saved model in front, as one
   > named undo step behind Heron's Keep or Discard prompt in Revit - that prompt and that one group are how
   > it is watched, and watched is not contained. Nothing it did stays unless the modeller, having seen the
   > result, presses Keep.

2. **Golden Rule 18 reads:** *"New code runs watched, not contained — or against a detached copy. Promotion
   to live comes after it passes."* Its title, its *Why* and its *Broken once, on the record* paragraph are
   unchanged.
3. **Nothing about the behaviour changes, and no requirement moves.** *Watched* is what the code does today: a
   new agent's first run is handed a world whose Revit door and production scopes are shut, every attempt to
   open one is written down, and the run is marked so it can never count as evidence
   (`heron_sandbox.py`, D-84); a DRAFT fragment's one run on a live model is the
   group held behind Revit's Keep or Discard box (D-119), and any other change from it is refused before
   anything is sent (D-117).
4. **What keeps its name.** `heron_sandbox.py` and `HERON-AHR-SBX-016` are names, and D-84 took the word out of
   their text, not their names. **Part 4 §10**, *Sandbox System*, is the owner's verbatim request for a
   component, not a rule that binds an agent: its words stay as written, and its dated *As built* note already
   says nothing contains new code.

### Alternatives considered

- **No** - the word stays, and D-84's consequence line is the sentence corrected instead (F23's own *no*).
  Rejected: Article 11 would go on telling an agent that a containment exists.
- **Build the containment** - a separate process with the ambient capabilities removed. D-84 chose not to, and
  that choice is unchanged.

### Consequences

- **Article 11 and Golden Rule 18 promise what the code does.** An agent given Article 11 is told new code is
  watched, not that it is held where it can reach nothing.
- **One design document still says it.** [docs/06](../06-heron-platform.md)'s *Proposed hard boundaries* note,
  point 3, reads *"New agents run in a sandbox first"*. It does not bind, and it is recorded as
  [row 5b-1751](../fragment-issues/row-5b-1751.md), not changed here.
- **No code, module, suite or instruction changes.** The Articles are read from the file, so the new words
  are what any instruction that assembles Article 11 now carries.
