# D-177 — An idea taken from another project is written in Heron's own words, and the project and its author are not named

> One record of [the decision log](../DECISIONS.md). Decisions are append-only: to change one, write a
> new decision that supersedes it.

### Context

Heron studies other projects and takes ideas from them, never code ([D-25](D-25.md),
[31 research](../31-research.md)). Until now its research notes named each project, its
repository and sometimes its author, as a citation. Research note 51 did the same for the project it
studied. The owner's view: Heron takes only the idea, so there is no reason to name whose idea it was.

### Decision

1. **A research note, proposal, decision, card, skill, code comment, commit message or pull request that
   takes an idea from another project does not name the project, its repository, its product or its
   author.** It says the idea came from studying another project, and describes the idea in Heron's
   own words.
2. **Nothing that would name it in another way either:** no link to it, no file path or identifier
   that carries its name, no quotation that carries its name.
3. **Heron's own evidence is named as always.** A claim about what Heron has still names its file,
   decision or command. A claim about the other project is said as its observation, without a source
   anyone could follow back to it.
4. **The code rule is unchanged:** nothing is copied, as [D-25](D-25.md) says.
5. **Older documents are not rewritten by this decision.** Research notes written before it still name
   the projects they studied. Taking those names out is a separate change, made when the owner asks.

### What is not known

Nothing here runs in Revit. Whether a reader can still follow an idea's history without its source is
the cost of this decision, and it is accepted.
