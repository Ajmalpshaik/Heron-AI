### Context

[D-91](../decisions/D-91.md), accepted 2026-09-21, decides *"Files come from a signed GitHub release, named by
version."* [`release.yml`](../../.github/workflows/release.yml) builds each release as a draft; its header says
*"NOTHING HERE IS SIGNED. Stage 8 is code signing, it is deliberately last"*, and the notes it writes on every
release say *"Not signed."* The one published release, v0.1.0, was published by the owner on 2026-10-08
knowing it was unsigned - *"Publish v0.1.0 now"* - and [NEEDS-CHECKING Group AC](../needs-checking/group-ac.md)
records it as *"the owner's exception, made knowingly"*. What is checked instead is the checksum: the
installer verifies every download against the release's `checksums.txt` before anything reaches Revit's
Addins folder ([`ReleaseAssets.cs`](../../platform/Heron.Installer/ReleaseAssets.cs)). The choice to leave
signing last was written only in [07 §3](../07-installation-and-update.md) and in the plugin-extension work
note's Stage 8, a folder deleted at the end of its life ([Q-77](../open-questions/tier-2.md)).

### Decision

1. **Now, a release is versioned and checksummed.** It is named by version and carries `checksums.txt`,
   against which the installer checks every file it downloads before anything reaches the Addins folder -
   D-91's *"verified before it is used"*.
2. **It says plainly that it is unsigned.** Every release made before signing is built says so in its notes,
   as `release.yml`'s already do, and nothing that describes a release calls it signed.
3. **Signing is due before Heron is given to anyone outside.** Q-77 named two such moments as examples:
   Heron offered to anyone outside the owner's office, or the README's *please do not install this yet* taken
   out. Each waits for a signed release.
4. **Signed stays the bar.** [`heron_tag.py`](../../brain/heron_tag.py)'s refusal of an unsigned release is kept
   as what Stage 8 must meet. `release.yml` does not run it today, so that refusal has never met a real
   release ([Group AC](../needs-checking/group-ac.md)).

### Alternatives considered

- **Sign now** (Q-77 shape 2): a code-signing certificate - a yearly cost and a renewal, the reason
  [Group AA](../needs-checking/group-aa.md) AA9 gave for not signing the deploy script - and a signing step in
  `release.yml` whose key lives in the credential store.
- **No more published releases until one is signed** (shape 3): a new teammate would install from a clone
  and a build instead of the installer's download.

### Consequences

- **An unsigned release is the rule on the record until signing is built**, not an exception. v0.1.0 is
  what this describes: versioned, checksummed, and saying it is not signed.
- **What the checksum does not do.** It catches a file damaged or swapped between the release page and the
  PC; it does not show who made the release. That is what the signature adds, and why it is due before Heron
  leaves the owner's hands.
- **The choice leaves the work note.** *Signing last* is recorded here now, so deleting the plugin-extension
  note loses nothing.
- **D-91's title still says signed.** A title is never rewritten (`check-decision-titles`); its index entry
  and its record say it was superseded in part, by this decision.
