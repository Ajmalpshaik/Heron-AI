### Context

[Article 7](../../HERON_CONSTITUTION.md) reads: *"Do not execute destructive Revit operations without
permission. Deleting elements, purging, bulk parameter writes, family reloads, workset changes and
anything touching a linked model require explicit confirmation for that specific operation."* On
2026-10-17 `revit_show` gave Heron a door that changes only what is on screen, and
`ZOOM_TO_LINKED_ELEMENTS` zooms the active view to elements inside a loaded link and, on Revit 2023 and
later, selects them as linked elements. Neither changes the model or the link. Whether that is
"touching" the link was put to the owner as Q-65, and until it was answered `revit_show` held such a fragment
until the user said yes (`heron_tools.link_refusal`, `link_confirmed`).

### Decision

1. **Selecting or zooming to elements inside a linked model is not touching it.** It needs no
   confirmation, and `revit_show` runs a capability that works inside a link like any other it may run.
2. **The hold is removed, not switched off.** `link_refusal`, `LINK_NEEDS` and `revit_show`'s
   `link_confirmed` are gone; `tests/test_read_door.py` holds that every fragment the show door may run
   goes through it whether or not it takes `linkName`, and that nothing in the door asks first.
3. **Changing a link is untouched by this.** Article 7's confirmation still covers anything that alters a
   link or what it brings in - and on `revit_change` it is still carried by the host's instructions, not
   by code ([FRAGMENT-ISSUES 5b-161](../fragment-issues/section-5b-rows-151-175.md)).

### Alternatives considered

- **Keep the hold** - the literal reading of "anything touching". One more chat turn before every zoom or
  selection inside a link, for an act Ctrl+Z has nothing to undo after. Not chosen by the owner.
- **Keep the function and stop calling it** - code that holds nothing, which a later change could wire
  back in by mistake. Removing it leaves one place, `door_refusal`, deciding what the show door runs.

### Consequences

- A chat zooms to or selects linked elements in one call, with Changes off.
- The decision is about the SCREEN: a fragment that reads a link was never held ([D-59](../DECISIONS.md#d-59--reading-spans-loaded-links-only-when-the-modeller-asks-and-the-answer-says-how-many-it-read)),
  and one that changes a link never reaches `revit_show` - `door_refusal` refuses anything above EXECUTE.
