### Context

A research note of 2026-11-15 (PR #877, idea 12) called installing Heron's most visible gap. Read against
the code on 2026-11-16, most of what it asked for was already built: `HeronInstaller.exe` and
`heron-install` install per user, one payload per Revit year, wait while Revit is open, check every zip,
read the runtime back out of what they copied, keep the old install, and set up Heron's Python side. What
was missing was **one file to download**, **an entry in Windows' Installed apps with Uninstall**, **a check
for a second copy of Heron**, **putting the old install back by itself when a copy fails half-way**,
**adding Heron to Claude Code**, and **a signature**.

Three shapes were put to the owner: wrap the installer, grow `HeronInstaller.exe` into a Setup, or replace
it with a new Setup holding every rule itself. He handed the choice to the session.

### Decision

1. **One file, `HeronSetup-<version>.exe`, made with Inno Setup.** Per user; it never asks for
   administrator rights. It puts the Heron folder in `%LOCALAPPDATA%\Programs\Heron AI`, carries every
   Revit year's payload as `tools/build-release-assets.py` makes it, and runs
   `heron-install --from <that payload>`. **It decides nothing about what goes where** - the engine does,
   as D-93, D-94 and D-96 require. Inno Setup was chosen over WiX because a per-user `.msi` is awkward and
   no decision makes an IT department's mass deployment a near goal.
2. **`heron-install --uninstall`** takes every Heron product off every Revit year it is on - never a
   selection, because a Windows Uninstall means *all of it*. What it removes is the screen's `ToRemove`
   with nothing ticked, so no second place decides what to delete. **`--uninstall --list` prints the
   screen's own confirmation, naming every product and release**, and the Setup's uninstaller shows that
   sentence and asks before anything goes. Every other `heron-install` line still never removes anything.
3. **A second copy of Heron is refused, per Revit year**, by `tools/deploy-addin.ps1`, so the window,
   `heron-install` and the Setup all get it: any other manifest in the folders Revit reads for that year
   that loads the same add-in id or the same assembly. Nothing for that year is changed, and the path is
   named.
4. **A copy that fails half-way puts the previous install back by itself**, from the backup taken a moment
   before, and says so. `-Rollback` stays for the case where the install finished and turned out bad.
5. **Claude Code is asked, never assumed.** A tick on the Setup's tasks page, **ON by default** - the
   owner's word on 2026-11-16 (*"yes, make both changes"*), because without it a new modeller would have to
   open Heron's program folder, under the hidden AppData, in Claude. It was first set OFF: on, every Claude
   chat in every folder starts Heron's server, and docs/WHAT-TO-INSTALL measured 2.0 to 2.3 GB per open chat
   on the owner's 16 GB laptop - with the optional search add-ons, which the Setup does not install; a plain
   install is not measured. The tick says so, and can be turned off. Only when no Claude is running; `~/.claude.json` is copied aside first; one user-scope server named `heron`, pointing at this
   Heron folder, with the `HERON_CLIENT_ID` the folder's own `.mcp.json` carries (one person, one id -
   D-22). No other key is touched, and the entry is read back. Uninstall removes it only when it points
   into this Heron folder. Where Claude Code keeps a user-scope server was read from its documentation
   on 2026-11-16: `~/.claude.json`, and a project's `.mcp.json` outranks it, so opening a Heron checkout
   still uses that checkout.
5a. **Heron's Python side is a tick too, ON by default** (the same word). Off, the Setup passes
   `--no-python`: for a PC whose Python somebody else manages, and for the owner's own test - building the
   knowledge store from the Setup's folder would change what every other chat on his PC reads.
6. **Signing: built in, and NOT RUN.** The Setup signs itself and its uninstaller when a certificate is
   handed to the build; with none it is built unsigned, and its build says so. **No certificate is bought
   by this decision** - D-96's reason, a yearly cost, stands until the owner says otherwise, and Q-77
   stays his.
7. **The Setup never writes `heron.config`.** Changes, Admin, Publish and Ask to Keep stay as they are:
   off on a new PC, byte-for-byte unchanged on one that has them.

### Alternatives considered

- **Grow `HeronInstaller.exe` into the Setup.** No new tool, but Heron would own a self-extracting,
  self-removing program that a Setup tool already is.
- **Replace the installer with a new Setup holding every rule.** Two install engines - against D-93, D-94
  and D-96 - and every lesson the engine already paid for (the wrong-runtime guard, the rollback, the
  Store-Claude refusal) learned again.
- **A WiX `.msi`.** What an IT department expects; awkward per user, and heavier.

### Consequences

- **A modeller's door is the Setup.** [07](../07-installation-and-update.md) and
  [WHAT-TO-INSTALL](../WHAT-TO-INSTALL.md) say so once it has run on the owner's PC; until then they are
  unchanged, because a door nobody has walked through is not one to send people to.
- **Inno Setup is needed only to BUILD the Setup**, not to run it.
- **Python is still the modeller's** - the Setup stops with the one `winget` line when it is missing.
- **The runs are [NEEDS-CHECKING Group OA](../needs-checking/group-oa.md)**: on the owner's PC for Revit
  2020, 2024, 2026 and 2027; 2021, 2022, 2023 and 2025 NOT RUN.

### Amended 2026-11-16 — the Setup's face is Heron's own window

**Accepted:** Ajmal PS, 2026-11-16, in conversation. Shown the Setup's pages, he called them basic and
asked for the company's look; offered *"the Setup opens the branded Heron Installer window instead of its
own pages"*, he answered *"Yes, do that"*, and confirmed it as one installer whose new parts all stay, with
only the face the old window.

What changes, and nothing else:

- **The Setup has no pages of its own.** It copies Heron's folder - a short copying page in the brand -
  then opens `HeronInstaller.exe --from "<folder>\payload"` and closes. That window, D-149's, asks
  everything and installs: the Revit years, then **items 5 and 5a's two ticks, which move into it, both
  still ON by default** - *Set up Heron's AI side* (unticked is `--no-python`) and *Add Heron to Claude
  Code* (offered only when the Setup opened the window; done last, and only after an install that failed
  nowhere). The window's `--from` is heron-install's: the same refusal by name and the same checked zips,
  and nothing is downloaded.
- **The Start-menu shortcut opens it the same way**, with `--from`; without it the window would take the
  download route this Setup exists to avoid.
- **A Heron Installer left open from the folder stops the Setup and the uninstall** before a file is
  touched - its exe is in the folder they replace or remove.
- **Run silent** (`/SILENT`, `/VERYSILENT`), nobody can press Install, so heron-install does the same
  install by itself and keeps its report as `setup-report.txt` - NOT RUN on the real Setup (row OA19).
- **The window's Remove Heron still takes Heron out of Revit and only that.** Installed by the Setup, the
  program folder and the Claude Code entry come out through Installed apps (item 2), and the window says
  so after a removal.

This is not the alternative refused above: the Setup still owns copying, the Installed-apps entry and
removal, and the window stays the face of the one engine. The runs are new rows in
[Group OA](../needs-checking/group-oa.md); the earlier rows were run on the Setup's own pages.
