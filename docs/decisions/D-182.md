### Context

A modeller's weekly round trip is parameters out to a spreadsheet, edited, and brought back: `EXPORT_PARAMETERS_TO_CSV`
writes the file and `SET_PARAMETER_VALUES_BY_ID` reads it back through `csvPath`. Read off both cards, the return
wrote every cell with nothing shown first (row 5b-1525), read a file of no said encoding (row 5b-1528), and could
refuse whole a file the export had just written (row 5b-1526). [Q-87](../open-questions/tier-2.md) was decided on
2026-11-15 on the owner's delegation and built that day as [`heron_sheet_compare.py`](../../brain/heron_sheet_compare.py);
on 2026-11-20 he confirmed it as his own, and handed row 5b-1526 - how the two halves agree about a column - to be
investigated and decided.

**What the investigation found, 2026-11-20, read off the code - not run in Revit.** With the comparison on the
route, a type parameter, a read-only one or one some elements have not got is sent only when the modeller edits it,
and refusing such a cell is right. One false refusal is left, and the comparison makes it common: the small file
has a column for every parameter that changed and a row for every element that changed, so each element's row is
blank under every column it did not change. The return looked for a cell's parameter BEFORE it looked at whether
the cell was blank, so in a mixed set - ducts and air terminals, a column one kind has not got - the whole file was
refused for a cell nobody asked it to write, with nothing the modeller could fix in the edited copy. The method said
so and had no remedy.

### Decision

1. **Compared first, outside Revit** (Q-87 (a), shape 2). The modeller keeps the file as exported and edits a copy;
   the comparison lists the changed cells, old and new, and writes ONLY those to a small file, which the return reads
   with `blankCells=skip`. A cell emptied on purpose is asked about apart.
2. **The file is read in Python first** - a CSV or an `.xlsx` - and a damaged cell, one holding a replacement
   character, is never sent (row 5b-1528).
3. **No chat tool for it** (Q-87 (b), door 3). The comparison is a command the modeller runs on their PC, named in
   the method.
4. **On the delegation: under `blankCells=skip` the return leaves a blank cell as it is BEFORE it looks for that
   cell's parameter** - `SET_PARAMETER_VALUES_BY_ID` version 10. A cell with a value still needs its parameter, once
   and writable; under `clear` a blank still needs a text one to empty. A column every cell of which was blank is
   named in the answer's findings. Every other route of the card - by id, by key, a pattern - is unchanged.
5. **On the delegation: the export gains no UniqueId column and no per-column warning, for now** (Q-87 (c)).

### Alternatives considered

- **A per-column warning in the export** - *on the type*, *read-only*, *not on N elements*. Not taken: the method's
  step 1 already reads `REPORT_PARAMETER_INVENTORY` and says which columns cannot come back before the file is made,
  and the comparison sends nothing from a column left as exported. A second place saying the same thing would cost
  the export's proof and still not end the false refusal.
- **A UniqueId column in the export.** Not taken now. It would send `EXPORT_PARAMETERS_TO_CSV` back to DRAFT, so the
  round trip would wait on two Revit runs instead of one, and it guards one case only - a file brought back to
  another model whose ids happen to be in use. A copy of the same file, made by Save As, keeps its elements'
  UniqueIds, so it would not catch the likeliest wrong model and would read as a guarantee it is not. The method
  already says the file comes back to the model it came from and names that model before the yes. The return
  already reads a UniqueId column where a file has one, so adding it later is the export's change and the
  comparison passing it through - never the return's.
- **The card compares the file with the model** (Q-87 (a), shape 3). Not taken: the owner's own decision is shape 2.
- **A small file per set of changed columns**, so no cell is ever blank and no card changes. Not taken: one request
  would become several calls and several entries in Revit's undo list (Article 8), and a later file refused after an
  earlier one was kept leaves the job half done.

### Consequences

- `SET_PARAMETER_VALUES_BY_ID` is **DRAFT at version 10** until Group NJ's NJ5 and NJ14 are run on a real model. Until
  then `revit_change` refuses a kept change from it - the round trip's return, the Companion's table Apply and its
  rows by key alike (D-117). The owner's standing word: a real defect in a PROVEN tool is fixed even if it goes back to
  DRAFT, and he proves it again.
- Still not reached, and said in the method: a value changed in Revit since the export, in a cell the modeller also
  edited - only a read of the model, or a UniqueId column carrying the old value, reaches it - so the file comes back
  in the same sitting; and `written` counts cells, not changes.
- Tested off Revit: [`tests/test_sheet_compare.py`](../../tests/test_sheet_compare.py) reads the order in the card's
  C#, and failed on version 9 before the change. The card compiles on every release 2020 to 2027
  (`tools/check-fragments-compile.py`, 2026-11-20). Not run in Revit.
