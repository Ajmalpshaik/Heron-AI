### Context

Each part of Heron picked its own colours as it was built. The add-in's windows highlight in blue
`#2F9BE3`, the activity banner keeps sixteen colours of its own, the ribbon's padlocks are red and blue,
and the Companion page and each report have their own palettes and fonts. Twenty-two source files set a
colour, and no two parts agree. On 2026-11-07 the owner handed over a brand kit and asked that it govern
every colour from now on - in what exists and in what is built later.

### Decision

1. **`docs/brand/README.md` is the one palette.** Its colour table holds every colour Heron shows: the
   style sheet's three (Ink, Mist, Accent), the status design's five (Accent Light, Surface, Success,
   Warning, Error), White from the app icon and a see-through Shadow - each one a hex value found in the
   owner's folder, none chosen here. The status design's other colours draw the pretend Windows desktop
   behind the notification and are not Heron's. A shade is one of these at an opacity, not a new
   colour.
2. **Nothing Heron shows uses a colour outside that table.** A new window, page, report or icon takes its
   colours from it. A colour that is missing is asked of the owner and added to the table **before** any
   code uses it.
3. **The font is Manrope**, with the system font as the fallback until a window or page carries it.
4. **Logos and icons come from `docs/brand/`.** Nobody draws a new logo; a ribbon icon is drawn in the
   brand's colours.
5. **Accent never means danger.** Orange is the everyday highlight. A state that must be noticed - a
   switch that lets Heron change the model, a failure - is Error.
6. **A Revit model's colours are not the brand.** What a fragment writes into a model (a duct's colour by
   system, a room fill, a material) follows the project's standard. `brain/fragments/` is outside this
   decision.
7. **`tools/check-brand.py` names every colour outside the table**, reading the table itself so no second
   copy exists. It is a report while the existing parts are brought into line - a finding is work still
   owed, not a red pull request - and becomes a gate once they are.

### Consequences

- **Easy:** one look across Revit, the Companion, reports and GitHub; a new window has its colours
  decided before it is drawn; the checker shows how much is still owed.
- **Hard:** the existing windows, icons, page and reports have to be redone. That is owed in two changes
  after this one: the Revit side (windows, banner, ribbon icons, tested in a real Revit) and the
  Companion page, reports and installer.
- **Not decided here:** a monospace font for codes and numbers, and a sequence of chart colours for
  reports with many categories. Neither is in the kit; both are asked of the owner when the reports are
  redone.
