### Context

D-131 let a PROVEN fragment carry the further releases it is proved on as entries of `proof.releases`, and
its Consequences named the one reader it did not reach: HERON-FRG-PRF-002, `heron_runs.measure`, read only
the release the proof names, through `heron_matrix.proof_release`. So failed runs on a release proven by an
entry were never reported as `contradicted`, and an entry with no runs at all was never
`unwatched_since_proof`. The evidence D-131 made recordable was the one evidence the run checks could not
see.

### Decision

1. **`measure` checks every release in `heron_matrix.proven_releases(fragment)[0]`** - the proof's own and
   every fresh entry - by the same rule, and each finding names its `source`: `proof` or `proof.releases`.
2. **The proof's own release is checked first.** `contradicted` and `unwatched_since_proof` stay one map
   each, the first finding of its kind, so a caller that read them before reads the proof's own whenever
   the proof has a finding. `contradicted_all` and `unwatched_all` carry every finding.
3. **`proof_on` stays the proof's own release**, read by `proof_release` exactly as before. The releases
   fresh entries stand on are `entries_on`.
4. **A stale entry is not checked**, and the answer names it in `stale_entries` rather than dropping it
   without a word. HERON-FRG-MTX-009 records a stale entry and does not count it; this agent follows that
   rather than deciding it a second time.
5. **An entry on a fragment no longer PROVEN or PRODUCTION is not checked** - `proven_releases` returns
   nothing for one. The proof's own release still is, as before, so no caller loses a finding it had.

### Alternatives considered

- **Make `contradicted` a list.** Every finding under one key, but every caller reading
  `contradicted["revit"]` breaks, and the contract change becomes BREAKING for a gap that did not need it.
  Not chosen.
- **Check stale entries too.** An entry taken against code that has since moved is evidence about code that
  no longer runs, and setting a failure today against it would set two records of different code against
  each other. Not chosen.

### Consequences

- One fragment can now be both contradicted and unwatched, on different releases. On any one release the
  two still never both fire, and `tests/test_runs.py` holds that.
- HERON-FRG-PRF-002's contract is **1.1.0**: four output fields added, which `heron_contract.compare` calls
  COMPATIBLE.
- **Checked without Revit, and only on fixtures.** `tests/test_runs.py` §8 holds the five rules above; with
  the old module in place 11 of its checks fail and none crash. CI was green on the head that merged. No
  run of a real Revit has gone through it: nothing outside its own suite and its demo calls `measure` with
  recorded runs yet, so this changes no answer anyone is given today. Which fragments carry an entry at all:
  `grep -l '^  releases:' brain/fragments/*/fragment.yaml`.
