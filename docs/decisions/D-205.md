the status nudge's span of it (`QUALITY_SPAN`, about 0.61 of one fusion rank), the card that changes nothing

### Why it was rejected

Built at 0.61, it failed `tests/test_brain_reachable.py`. The change request *"join this roof to that roof"*
went from its write `SHAPE_WALL_TOPS_TO_ROOF` to the read `REPORT_ROOF_REACH`, which was **0.23** of a rank
behind. The questions the rule helped have their reads 0.41 behind (*"what export settings are there"*) and
0.49 behind (*"How many sheets are there for the duct layout?"*).

A margin wide enough to help either question therefore takes that change request off its write. A margin
narrow enough to keep it helps no question. The two routes' places do not separate the two kinds either: in
the roof request and in the export question alike, the read is nearer by meaning and further by words. A rule
that did separate them would have to read the words, which D-01 forbids. The owner asked for a safe margin,
and there is none on this library.

### Consequences

- No code changed. A question still reaches a write only when the host leaves `question` off. With the flag,
  his 79 and the 124 plain questions reach no write (D-128).
- Asking again needs a library where the change requests' near-ties and the questions' near-ties no longer
  overlap, measured with every routing suite, `test_brain_reachable` included.
