## Group NR - three everyday MEP jobs given a method, none run in Revit: annotate a view, colour a view by system, spaces and zones from the architect's link (2026-11-12)

Three jobs a services modeller does every week had every capability and no method, so a chat was handed one
card at a time and had to work the order out. Each is a method now, written on 2026-11-12 in a cloud
container from the cards' own contracts and, where a step turns on it, their C#:
[`annotate-a-view`](../../brain/skills/annotate-a-view.yaml),
[`system-colours`](../../brain/skills/system-colours.yaml) and
[`hvac-spaces-and-zones`](../../brain/skills/hvac-spaces-and-zones.yaml). No new capability and no new
tool. **None of the rows below has run.** Each method stays DRAFT until its own rows have.

**The PC, on the Revit release the owner works in. A SAVED scratch copy of a services model with ducts on at
least three systems, and for NR7 to NR11 an architect's model linked into it with placed, numbered rooms on
two levels - never the owner's own file.** The owner has Changes on, and *Ask to Keep* ON so that every
change is asked - it is OFF on a PC as installed (D-138), so turn it on in Heron's Settings first; NR12 is
the one row run with it off. **Press
Discard at every Keep or Discard box unless the row says Keep**; a row that keeps says when to Undo. Each
run is asked in a chat, so that what is measured is what a modeller would get.

A row that comes out differently from *Look for* is a finding: say what Revit answered, word for word, and
correct the method's step - and the FRAGMENT-ISSUES row, where one is named - that it contradicts. Nothing
in a row is changed to make it pass.
