**What is done and what is not.** All nine compile for all eight releases, 2020 to 2027
(`tools/check-fragments-compile.py`, 2026-11-01), and every Revit member they call was read off the shipped
assemblies of all eight (`tools/api-surface --members`). A member missing from a release is reached by name at
run time and refused on that release in plain words. **Nothing here has run in Revit.** All nine cards are DRAFT.
Main's PR #777 had already made four of the widened cards DRAFT when it merged the duplicates into them; this
change returns one more, `SET_SCHEDULE_SORT_GROUP`, from PROVEN to DRAFT. The old proofs are kept on the cards
as records, and `revit_change` refuses a DRAFT until it is proved here and signed.

**The models - five scratch projects, never a 4355-* job model.** Each job file builds its own from Revit 2020's
default metric template and says how, so their schedule names cannot clash: `Heron Schedules KF Appearance`,
`... KF Sorting`, `... KF Options`, `... KF Kinds`, `... KF Fields`. For the rows marked *2021*, *2022*, *2023* or
*2024 or later*, a copy of the same project saved in that release. Every job file reads back with `--dry-run`
and sends nothing. Proving waits for Ajmal PS's word.
