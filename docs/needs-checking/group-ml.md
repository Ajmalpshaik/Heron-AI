## Group ML - Modify > Justification, Annotate > Tread Number and Manage > Project Parameters > Remove - set and read where beams and braces sit on their line, place tread or riser numbers on a stair run, and remove a project parameter: `SET_FRAMING_JUSTIFICATION`, `REPORT_FRAMING_JUSTIFICATION`, `PLACE_STAIR_TREAD_NUMBERS`, `REMOVE_PROJECT_PARAMETER` (2026-11-02)

Asked for as three gaps on Revit's ribbon: *"beam / brace justification - set and read the structural framing
yz-justification, y/z offsets and start/end level offsets"*, *"stair tread/riser numbers - place tread or riser
numbers on a stair run in a view"* and *"remove a project parameter - Manage > Project Parameters > Remove"*. No
card did any of them: a grep of every fragment's C# that day for `YZ_JUSTIFICATION`, the `*_OFFSET_VALUE`
parameters and `STRUCTURAL_BEAM_END0_ELEVATION` found only `COPY_ELEMENTS` (which reads the level offsets to copy
a beam), for `NumberSystem` none, and for `BindingMap` `Remove` none. `brain/heron_retrieve.py` (Revit 2024, a
scratch store) sent *"set beam justification to top"* to `PLACE_BEAM_REBAR`, *"add tread numbers to the stair"* to
`CREATE_STAIRS` and *"remove the project parameter Fire Rating"* to `WRITE_ELEMENT_PARAMETERS`.
heron-duplicate-checker's method (`heron_duplicates.look`: 0 already here for each) found look-alikes only:
`SET_FRAMING_END_EXTENSION` (end extension and join cutback - left out here, as asked), `SET_MEP_JUSTIFICATION`
(ducts and pipes), `READ_ELEMENT_PARAMETERS` and `WRITE_ELEMENT_PARAMETERS` (one parameter named exactly),
`TAG_ELEMENTS_IN_VIEW` (tags, not tread numbers), and `ADD_PROJECT_PARAMETER`,
`TRANSFER_PROJECT_PARAMETERS_BETWEEN_DOCUMENTS` and `DELETE_FAMILY_PARAMETERS` (bind, copy, or delete in a
family - none removes a project parameter). So four new cards: the request's *"set and read"* is a write and a
read, because a question never reaches a write ([D-86](../DECISIONS.md)).

**Why ADMIN, when every element delete in the library is MODIFY.** `DELETE_FAMILY_PARAMETERS`' card gives the
library's rule - MODIFY for a change inside the document, *"and ADMIN is project setup"* - and
[D-106](../decisions/D-106.md) names what ADMIN guards: *"changes to how the project is set up: a project or global
parameter"*. `ADD_PROJECT_PARAMETER` and `TRANSFER_PROJECT_PARAMETERS_BETWEEN_DOCUMENTS`, the two cards that bind
one, are both ADMIN. Taking a binding away is the same change backwards and loses data, so it sits behind the same
Admin switch - and the switch never says yes on the owner's behalf, so `confirm` carries Article 7 as well. No
batch and no `try-once` sends an ADMIN card; it is proved by name, ML6.

**What is done and what is not.** All four compile for all eight releases, 2020 to 2027
(`tools/check-fragments-compile.py`, 2026-11-02, a Linux container). Every Revit member was read off the shipped
assemblies of all eight with `tools/api-surface --members`, named in each card's `compatibility-note`;
`StructuralFramingUtils` has no justification member on any release (its ten methods are end joins, end
references and `FlipEnds`), so the parameters are the API; `BuiltInParameter.NUMBER_SYSTEM_START_NUMBER` is 2027
only and is looked up by name at run time. **Nothing here has run in Revit.** All four are DRAFT. **Only Revit can
settle**, and ML2 to ML6 record: the numbers behind each justification choice (row 5b-1445); which Tag Type number
means Riser, and whether Revit 2027 numbers from the numbers' own Start Number or the stair's (row 5b-1446);
whether `NumberSystem.Create` takes a section view; and what `Document.Delete` of a parameter that is not shared
does to the schedule column that showed it (row 5b-1447).
