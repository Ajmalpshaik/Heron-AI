## Group NQ - three everyday MEP jobs given a method, none run in Revit: annotate a view, colour a view by system, spaces and zones from the architect's link (2026-11-12)

Three jobs a services modeller does every week had every capability and no method, so a chat was handed one
card at a time and had to work the order out. Each is a method now, written on 2026-11-12 in a cloud
container from the cards' own contracts and, where a step turns on it, their C#:
[`annotate-a-view`](../../brain/skills/annotate-a-view.yaml),
[`system-colours`](../../brain/skills/system-colours.yaml) and
[`hvac-spaces-and-zones`](../../brain/skills/hvac-spaces-and-zones.yaml). No new capability and no new
tool. **None of the rows below has run.** Each method stays DRAFT until its own rows have.

| What the methods rest on, and it is not yet seen | Read from | Row |
|---|---|---|
| A filter of tag categories hands `ARRANGE_TAGS` its tags, and a second overlap read comes back clear | the cards' contracts and proof records - each proof ran one tag category a call | NQ1, NQ3 |
| `CREATE_VIEW_FILTER` with `perValue` puts one filter a value on the view in its own colour, skips a name the project has, and `COPY_VIEW_FILTERS` carries the colours | the card's C# | NQ4, NQ5 |

| Spaces made from a link that is Room Bounding and KEPT read back with an area ([row 5b-1125](../fragment-issues/section-5b-rows-401-425.md): the proof's spaces had none, inside a change that was rolled back) | the card's proof | NQ7, NQ8 |
| With a phase that is not the model's last, a second run does not see the first one's spaces ([row 5b-1580](../fragment-issues/row-5b-1580.md)) | the card's C# and Revit's API reference | NQ9 |

**The PC, on the Revit release the owner works in. A SAVED scratch copy of a services model with ducts on at
least three systems, and for NQ7 to NQ11 an architect's model linked into it with placed, numbered rooms on
two levels - never the owner's own file.** The owner has Changes on, and *Ask to Keep* ON so that every
change is asked - it is OFF on a PC as installed (D-138), so turn it on in Heron's Settings first. **Press
Discard at every Keep or Discard box unless the row says Keep**; a row that keeps says when to Undo. Each
run is asked in a chat, so that what is measured is what a modeller would get.

A row that comes out differently from *Look for* is a finding: say what Revit answered, word for word, and
correct the method's step - and the FRAGMENT-ISSUES row, where one is named - that it contradicts. Nothing
in a row is changed to make it pass.
